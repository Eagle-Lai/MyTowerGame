## 2. 本次实际改动清单

### 2.1 效果图（10 处）

| 文件 | 改动 |
|---|---|
| `15_SplashView.svg` | 标题 →「自由人塔防」；标注引线 `x1` 744→**712**（避开变宽的标题左缘） |
| `18_MainMenuView.svg` | 标题 →「自由人塔防」；**标题基线 470→488、副标题 524→540** |
| `16/17/19/20/21/22_*.svg` | 注释数据源 → `ArtDesign_自由人塔防_补全策划案_v1.md` |

⚠️ **为什么 18 号图必须改基线**：5 字名在 88 号下实宽 **440px**（原 4 字名 352px），「人」字撇捺下探到 y_svg 497，与 26 号副标题墨迹顶（516）仅剩 19px —— 渲染出来是**糊在一起的**。改后间隙回到 19px。

> **教训**：改文案长度后必须**按字体实测墨迹区间重算间距**，不能只看控件框尺寸。
> 方法：`PIL.ImageFont.truetype(字体, 字号)` → `getmetrics()` 取 ascent/descent、`getbbox(text)` 取墨迹区间；
> 墨迹上沿 = `baseline + bbox[1] − ascent`，下沿 = `baseline + bbox[3] − ascent`。
> SVG 语义（`text-anchor=middle` + y=基线）在 PIL 里用 `anchor='ms'` 复现。

## 3. 明确定为「不改」的项（附理由）

| 项 | 规模 | 不改的理由 |
|---|---|---|
| **YooAsset 包裹名 `FreeTower`** | 3 个配置/代码文件 | 它是 **AB 输出目录名**（`Bundles/Android/FreeTower/1.0.0`）。改了已构建的 AB 与热更地址全部失效，且 `BundleCollectorSetting.asset` 是 YooAsset 序列化配置，改错会导致收集器读不到设置 |
| **命名空间 `FTProject`** | 112 个文件 | 纯内部标识符，用户不可见。改它要同步全部 `using`，风险远超收益 |
| **存档文件名 `freetower_*`** | 4 个文件 | ✅ **这正是不受改名影响的原因**。文件名基于英文名，与中文游戏名无关 → **用户已有存档不会失效** |
| **Unity 菜单 `Tools/塔防/...`** | ~40 处 `MenuItem` | 「塔防」是**玩法类型**不是游戏名（如「Tools/塔防/3. 导出配置表」） |
| **指原版 Fieldrunners 的引用** | 8 处（含 3 处代码注释） | 如「对标《坚守阵地》（Fieldrunners）」「这是《坚守阵地》的核心机制」。改成本工程名会变成**自指错误** |
| **`Docs/YooAsset_Integration.md`** 2 处 | 2 处 | 是实际运行日志样本（`包裹=FreeTower`），包裹名未改则应保留原样 |
| **`Luban/Config/.cache.meta`** | 1 个文件 | Luban 构建缓存，记录的是过期路径 `E:/_FT/FreedomTower/...`；不影响导出功能（Luban 会自行重建） |

## 4. 未来改名时的检查清单

按影响面从大到小排查，**顺序很重要**（先查会坏事的，再改文案）：

1. **存档机制** → 查 `Data/Persistence/` 的文件名常量。若含中文名则改名会**让用户存档失效**，必须做迁移。
2. **代码标识符** → 命名空间、类名前缀。改要全量同步。
3. **资源标识** → `ResTable.cs`、YooAsset 包裹名、AB 目录。改需重新打全部资源包。
4. **工程配置** → `ProjectSettings.asset` 的 `productName` / `companyName` / `applicationIdentifier`（含 Standalone 与 Android 两处）/ `metro*`。
5. **效果图** → 先按 §2.1 的字体度量法**重算标题间距**，再改文案；改完必跑：
   ```bash
   python .workbuddy/tools/check_svg_layout.py    # 期望 0 重叠 0 越界
   ```
6. **文档** → H1 标题、交叉引用、文件名（用 `git mv` 保留历史）。改完验证：
   - 旧名残留扫描
   - 交叉引用断链扫描（`Docs/<name>.md` 是否都真实存在）
7. **区分"本工程名"与"原版引用"** → 每次遇到旧名都要先判断**指谁**，原版游戏的引用不能改。
