## 三、通用美术规则

### 1. 以原设计为视觉基准

调用可用的图像生成或图像编辑能力前，先读取相应技能说明。使用当前原始图集和从原预制体渲染的完整角色作为参考；必要时补充分件、姿态和特征局部图。

新增方向必须对齐原侧面的色调、色彩分区、描边粗细、轮廓、身体比例、材质、明暗和卡通风格。正常、愤怒、死亡等表情均遵循同一套设计，不能因生成不同视角或动作而出现明显色差或身份变化。存在旧参考或旧生成图时，以当前原始资源为准，不把过时设计当作最新基准。

检查实际返回图片的格式与尺寸，再进行去底、裁切和导入。保留生成输入、提示词、结果和处理过程，控制生成次数并复用合格结果；请求超时先确认是否已有结果，避免盲目重复计费。

第三方 Image API 的地址、模型、鉴权和密钥处理遵循工程 `AGENTS.md` 的现有授权与规则，不输出、落盘或提交明文密钥。如能力不可用，应明确说明未完成的美术，不以占位资源冒充完成。

### 2. 按观察方向重建设计

- Up 表示向屏幕上方移动时的背向表现，Down 表示向屏幕下方移动时的正向表现。先核对实际相机、世界移动方向和现有透视风格，保持战场机位。
- 上下方向必须是真实对应视角，不得用侧图旋转、上下翻转或拉伸充当。左右对称分件可按角色结构合理镜像，但镜像不能代替视角设计。
- 正面和背面的头部、躯干、肢体及附肢应符合角色自身结构。身体连接位置、关节朝向、弯折方向、前后层次和遮挡必须合理；不能将侧面姿态直接平移到正背面。
- 正面附肢应自然连接躯干，根部与身体的遮挡符合视角；背面应呈现对应的后躯结构，不能仅复用正面腹部。
- 原设计具有尾巴、尾羽、背甲、耳角、鬃毛、装备或其他标志性结构时，按当前视角补齐可见部分，保留合理连接、轮廓和遮挡。形状、大小和摆动依据各角色原设计，不统一套用某种尾部或附肢。
- 双足或多足角色的腿根应连接到合理部位，并由躯干按视角适当遮挡；足部朝向、落点和步幅与移动方向一致，避免脱节、外露关节、悬空或穿插。
- 各方向体型、视觉中心和脚底接地点应协调，转向时不明显跳位、漂浮、拉伸或突然缩放。

### 3. 所有方向统一不使用地面阴影

示例及后续逐个适配的所有敌人，在 Left、Right、Up、Down 全部方向移除角色地面阴影表现。删除战斗预制体中相应的阴影节点或渲染器，不只缩小阴影、降低透明度或在部分方向隐藏。

新增图片本身不得绘入地面阴影；受击、死亡、切向、重新寻路和对象池复用均不得恢复阴影。单预制体接入及后续重建必须重复应用这一规则。

保留原始图集、源预制体及共享资源作为参考，避免删除仍被其他资源引用的源文件。原始对照图如包含历史阴影，应明确标注，不与当前成品混淆。

本条在逐个完成方向适配时应用；示例审核前仍不得批量改动其他敌人。

### 4. 分件、透明边缘与动画

优先沿用现有分件方案，补齐对应方向的头部、身体、肢体、附肢及必要姿态。新增结构可根据动画和遮挡需要独立分件，也可合理合入现有身体切片；不要为静态细节增加无必要的运行组件。

保留原始图集。示例新增资源放入 `E:/MyTowerGame/Assets/_UIAssets/Monsters/Birds/AdvancedHen/Directions/`；后续使用各角色自己的 `Directions/` 目录，清楚命名方向、分件和动作。

交付真实透明背景 PNG，检查透明边缘、去底污染、低 alpha 噪点、裁切和描边完整性。正确设置切片、Pivot、PPU、渲染顺序及平台导入参数；不同表情应有稳定的尺寸和对齐基准。保持精灵与新增依赖的 GUID，局部迭代优先保留无关切片和动作。

上下方向须有可循环的行走表现，并承接待机、准备、奔跑、攻击和死亡。侧面动画不适合新增视角时，制作对应姿态或专用动画，不强行套用错误运动。允许沿用既有动作复用关系，不要求凭空新增原工程没有的独立状态。

尾部、附肢和装备应跟随合理的身体运动，并正确参与受击、死亡和复用。循环动作首尾连续，普通转向保持当前动作相位。

## 四、方向逻辑与运行接入

1. 根据实际世界移动向量选择 Left、Right、Up、Down。斜向采用主轴判断，并设置合理容差或滞回；接近零位移时保留最后有效方向，避免在分界附近抖动。
2. 兼容地面寻路、飞行直线移动、出生、路径刷新和对象池复用。启用四方向的角色应以当前第一段有效移动设置出生朝向，跳过重复和近零路径点，不能向后寻找未来横向段代替当前方向。
3. 左右保留原侧面美术和水平镜像，兼容 `Global.ArtFaceLeft`。进入上下方向时清除旧镜像影响，保持正确缩放、姿态和血条补偿。
4. 保持 Animator 契约：`State` 为 int，0=Idle、1=Ready、2=Walk、3=Run、9=Death；`Speed` 为 float，`Attack` 为 Trigger，兼容既有 `Action` 参数。专用控制器需保留状态、速度、事件和合理的动作复用关系；转向不反复重播行走。
5. 正常、愤怒、死亡头与当前方向一致。检查 `SetHead(int)` 等动画事件，避免事件把头切回侧面；事件接收节点和引用必须有效，攻击结束及再生后恢复正确表情。
6. 处理身体渲染器缓存、白闪、死亡淡出和收缩。当前方向可见的全部身体结构都应参与效果；致死白闪必须按时消退，不能遮住死亡表现。尾部或附肢不得残留不透明、错误颜色或重复身体。
7. Init、OnRecycle 和再次取出后恢复方向、正常头、可见性、透明度、缩放、白闪及 Animator 状态，不残留死亡头、半透明尸体、旧镜像或阴影。
8. 保持血条显示、扣血方向和 `CompensateHpBarFlip` 正常。删除阴影不能影响其他节点引用、对象池或身体缓存。
9. 沿用 `BaseEnemy.Tick` 集中驱动，不增加不必要的独立 Update、每帧层级查找、重复材质实例或额外分配。
10. 保持原资源逻辑名和战斗预制体路径。新增 PNG、Profile、材质、Shader、控制器和动画通过现有引用或寻址体系加载，并进入当前 YooAsset/AssetBundle 收集链路。仅在必要时最小化扩展寻址，不修改战斗配置解决美术问题。
11. 提供可重复执行的单预制体接入方式，缺图或配置不完整时明确失败，不安装占位资源。重复接入不得产生重复节点、丢失 GUID 或恢复阴影。
12. `MonsterPrefabBuilder` 后续重建时应保留或重新应用方向配置、专用控制器及无阴影规则。用临时克隆或单例入口验证，不运行全量怪物重建。
