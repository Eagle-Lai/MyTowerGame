# 敌人预制体串行续接协议

本协议用于在图片中转请求达到 32 MiB 后，把长任务拆成可恢复的短对话。它是执行 prompt 的交接补充，不改变原 prompt 的角色、验收或 Unity 规则。

## 每个对话只负责一个角色

1. 开始时读取根 `AGENTS.md`、Unity 版本、原始执行 prompt、本协议、实时 `progress.json` 和当前角色已有证据。
2. 从实时队列选择一个角色。若角色已经有安装或运行结果，先恢复当前阶段；禁止重复付费生成、删除安装清单绕过保护、或盲目从 `prepare` 重跑。
3. 对 `Assets/Prefabs/Enemy` 的生产修改一次只处理一个角色。该角色完成安装、两轮真实 Play、媒体审阅、record 和 GIF 归档，或记录真实阻断并交回 Unity 后，才允许处理下一个角色。
4. 图片只作为分次审阅输入。原件和完整帧保存在磁盘；每次优先发送 1～2 张预览和必要的局部，不一次发送全部角色、全部 GIF 或全部历史图片。单张大小预算只是降低风险的建议，不代表服务保证。
5. 在结束当前对话前，写入该角色的阶段状态、revision、运行计数、视觉审阅范围、证据路径、未完成项和阻断原因；更新 progress 与 prompt 的实时说明，不改写历史批准、失败和冻结证据。
6. 当前角色的交接记录落盘并确认可读后，主动创建唯一的下一对话，不等待用户逐角色确认。新对话只读取文件路径和必要文字摘要，避免继承旧聊天中的图片历史。创建成功后旧对话停止修改工程；新对话按同一协议继续，直到全部有效完成或只剩真实阻断。

## 对话创建边界

新对话可以由当前代理按用户已明确授权的循环目标创建，但创建本身是异步的，不能保证前一个对话已经安全结束，也不能自动绕过 Unity/MCP、付费请求、用户输入或真实阻断。每次创建前必须检查当前工作区和 `progress.json`，确认没有其他角色正在修改预制体。

本协议不允许创建并发角色任务。若新对话创建结果不明，先查实际聊天列表和返回记录，不盲目重试创建。Unity 未连接先按工程规则自主恢复；图片生成结果不明不重发付费请求。真实阻断须保留角色和恢复条件；安全交回 Unity 后，可以把唯一所有权交给下一个可独立推进的角色，不删除阻断项。全部可独立工作均耗尽时停止并报告。

## 完成一个角色后的自动接棒步骤

1. 确认本角色满足原 prompt 验收要求，使用现有 record 流程更新进度；若真实阻断则保留准确阻断与请求状态。既有结果和本轮新执行结果必须区分。
2. 在 `conversation_handoffs/` 新建带时间及角色名的总结，不覆盖旧记录。至少记录角色状态、实际修改、最终 revision、生产指纹、两轮结果与证据、实际审过的画面、范围审计、Unity 当前状态、未完成事项和下一候选。不写入图片 base64 或密钥。
3. 重新读取实时 progress.items。优先恢复已开始且可恢复的角色，再按 index 选择未完成项；不重复生成已完成角色，不盲用 progress.current。只剩阻断时记录 blocked 并停止；全部 108 项有效完成时记录 complete 并停止。
4. 更新原执行 prompt 中的自动续接实时块、`NEXT_ENEMY_TASK.md` 和链状态。NEXT_ENEMY_TASK 必须包含完整可执行的接棒说明、下一个唯一角色、总结路径与真实阶段，不使用占位符，不复制旧图片。原 prompt 的历史章节保留。
5. 先确认自己的 Unity 测试结束并恢复场景，没有编译、录像或其他任务占用；停止生产修改。将链状态改为 handoff_ready，生成新的唯一 dispatch_token，记下 parent_thread_id、下一个角色及总结路径。此时任何线程都不得改生产资源。
6. 调用 Codex 的 list_projects，确认 E:/MyTowerGame 的项目 ID；只创建一个全新本地聊天，prompt 中明确要求先读取上述文件及该 dispatch_token，等待链状态变为 active 且 token 一致再开始生产操作。不使用 fork，不启动分支并发任务，不更改模型或推理设置。
7. create_thread 的参数必须遵循现场 schema。当前文档结构是 `{target:{type:"project",projectId:"935c594c-f414-48e0-bd08-ed8ba342f7fd",environment:{type:"local"}},prompt:完整提示}`；projectId 属于 target 内部。此前把 projectId 放到外层导致 invalid arguments，属于参数错误，不能据此认定项目任务不可用。恢复时重新发现项目 ID。
8. 创建明确成功后，旧线程把返回的 threadId/hostId、新 token 及角色写回链状态，改为 active，并追加创建记录。新线程随后获得唯一生产所有权，旧线程只可做只读状态查询和发送交接信息，不能再修改生产资源或链状态。创建响应写不回时，新线程保持只读，报告具体故障。
9. 用一次有界 wait_threads 查询确认新聊天开始同步；若它请求用户输入或报错，保留真实状态，不通过另一聊天重复派发。旧线程最终回复给出创建结果及 `::created-thread{threadId="返回的真实ID"}`。

工具缺失或创建失败时，保留完整 NEXT_ENEMY_TASK 和总结，报告未成功自动接棒，不谎称后台循环已运行。不要为了绕过问题创建定时器、计划任务或多个工作代理。
