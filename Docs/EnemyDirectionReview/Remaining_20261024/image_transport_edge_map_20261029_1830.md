# 图像传输根因定案：aihub.dog 坏边缘 IP 与固定方案（2026-10-29 18:30）

本文件修正并取代 `WinterOgre/transport_recovery_verified_20261029_1520.md` 中"间歇性网络故障、故障窗口自行恢复"的判断，及 `WinterOgre/transport_fix_20261029.json` 中"切代理"的处置建议——**二者方向均错误**。既有证据文件一律未动。

## 根因（已用对照实验锁定）

aihub.dog 系统 DNS 返回 4 个 A 记录，其中 **216.236.62.x 两个边缘的图像编辑上游是坏的**：

| 边缘 IP | 鉴权探测（gpt-image-2/low/1024x1024/564B图） | 未鉴权 401 |
|---|---|---|
| **191.101.132.254** | ✅ HTTP 200，20.2s | 快速正常 |
| **191.101.132.62** | ✅ HTTP 200，19.1s | 快速正常 |
| 216.236.62.158 | ❌ Curl 52 空回复，**精确 10.02s** | 快速正常 |
| 216.236.62.159 | ❌ Curl 28 超时，21.0s | 快速正常 |

未鉴权 401 由边缘在上游路由**之前**返回，因此任何"不带鉴权的对照"都无法区分边缘好坏——这是上午误判"代理可用"的原因。

## 历史症状全部对号入座

| 症状 | 解释 |
|---|---|
| 直连 Curl 55/56、ECONNRESET（14:18~14:28、17:43~17:50，共5次） | 系统 DNS 轮询/缓存把 curl 指到 216.236.62.x 坏边缘，上传期被断 |
| 直连"间歇性"成功（15:15 T1/T2、16:xx WinterOgre Up05+Down、18:16 P1） | 当时解析/缓存命中 191.101.132.x 好边缘 |
| 走 Clash 代理必 Curl 52 @10s（14:28 revision_04、17:56 revision_02、18:17 本机复测 P2，3/3） | Clash 自有 DNS（223.6.6.6/8.8.8.8，fake-ip 模式，use-hosts=false）固定解析到坏边缘 |
| Curl 52 精确 ~10s / Curl 28 ~21s | 分别对应 .158（上游 10s 断开）与 .159（21s 超时）两种坏法 |

## 修复方案（对任务执行层）

**好边缘：`191.101.132.254`（首选）、`191.101.132.62`（备选）。坏边缘：`216.236.62.158`、`216.236.62.159`。**

generate.mjs 的 curl argv 增加一行（按你们的 tooling 变更协议留痕后应用）：

```
argv.push('--resolve', 'aihub.dog:443:191.101.132.254');
```

- 仅影响该请求的解析，不污染系统 hosts、不改变 Clash、失败可回退（删掉该行即恢复 DNS 行为）
- **不要走 `--system-local-proxy`**：Clash 的 DNS 会固定命中坏边缘，代理路径已证 3/3 全灭
- 不要写系统 hosts：Clash 的 `use-hosts:false` 使其对代理路径无效，且聊天线路（同域名）会被一起钉死，丧失故障切换能力
- 上游确认正常需 20~40s；若钉住好边缘后仍 >60s 无响应，才是真正的新故障

## 边缘健康复查命令（未来复发时先跑这个，免费→付费最小）

```bash
# 免费：4 边缘 TLS/401 行为
for IP in 191.101.132.254 191.101.132.62 216.236.62.158 216.236.62.159; do
  curl -s --noproxy '*' --resolve aihub.dog:443:$IP -m 40 -X POST https://aihub.dog/v1/images/edits \
    -F prompt=test -F 'image[]=@"/path/to/small.png";type=image/png' \
    -w "$IP HTTP=%{http_code} t=%{time_total}s exit=%{exitcode}\n" -o /dev/null; done
# 判定：好边缘应全部快速 401；若好边缘也开始 curl55/52，说明该 IP 也劣化，换 191.101.132.62 或重新解析
```
