# HUD「回到上波」实施与数据验收（2026-11-07）

工程：`D:/FreedomTower_1`，Unity `2022.3.62f3c1`，MCP 插件 `10.3.0`。沿用用户当次指定的 stdio / 6400，重新通过实例列表和 project/info 核对当前实体工程。连接信息不作为其它工程或下次会话的默认值。

## 玩家行为与边界

- 右上角顺序：暂停 / 重试本波 / **回到上波** / 菜单。实际 prefab 节点为 `Btn_PreviousWave`。
- 当前正在打第 N 波，或准备打第 N 波时，确认后回到第 N−1 波开打前的准备状态。波次按正式 Round 计算，包含整波所有出怪编组。
- 支持不先开打、连续回退：第 5 波 → 第 4 波准备 → 第 3 波准备 → 第 2 波准备 → 第 1 波准备。第 1 波准备态和第 1 波进行中不可再向前。
- 第 1 波的记录是**第一次点击开始之前的局面**：若此前布过塔，会按该记录恢复塔阵；若此前为空阵，就恢复空阵。回到该记录时关卡计时恢复为未开始。
- 每次点击均弹确认框，正文显示实际目标波号。弹窗暂停战斗和自动开波倒计时，P/继续/开始/其它重试请求都不能绕过。
- 取消和点击背景不改变进度，并恢复原先暂停状态。确认后取消自动开波，允许重新布防，再点开始重打。倍速档位保留。
- 回退后的准备态可继续回退。重试本波仍只在波次进行中可用，且恢复该次重新布防后的最新开波状态。
- 加载、退出、失败或通关结算后不可回退；已结算的星级/解锁记录不会被这条局内功能撤销。整关重新开始仍走原有入口。
- 历史只属于当前对局，退出、重开或切关即清空，不为历史缺失的续局伪造开波数据，不跨局或跨关引用。

## 数据一致性

每次正式开波前，用独立副本记录塔阵（类型、等级、格位、实际投入）、金币与小数余数、生命/最大生命、累计击杀/漏怪、完整运行统计、战斗/关卡计时与计时启动标记。

回退同时恢复波次游标和已完成波次账目，撤销目标波及后续的收益、损失、升级、建塔、卖塔和统计。清理当前敌人、塔、放置预览、选中状态、相关操作面板及飘字，刷新寻路。恢复后用回退边界状态覆盖本波内卖塔等产生的即时存档，存档计时使用检查点的精确值。存档 schema 和评级/星级语义未变。

历史按正式波次游标索引；回退后裁去目标波之后的旧记录，重新开打时替换目标波记录，保证新分支不再读取旧分支。运行调试标记只保留/累积，不能靠回退抹掉。

## 异常与重入

- 记录必须属于当前 levelId、runId、正式 roundId 和目标游标，资源/计时/统计结构必须有效；不存在或不匹配就阻止操作，不猜测恢复。
- 在清理当前局面前检查恢复依赖、塔配置、可建格位和重复格位。检查失败保持现有局面，并在 UI 请求中提示无法恢复。
- 确认框打开期间以及恢复期间，两条重试 API 均禁止重入。回调同时核对操作版本；切关/新开波后的旧回调不能再次操作新局面。
- 确认/取消只消费一次。确认框被关闭、禁用、销毁或被其它确认请求替换时，都会收尾取消回调，释放暂停/请求锁。
- 若实体恢复无法完整完成或遇到异常，则中止本局，不允许带不完整塔阵继续推进；异常收尾不遗留永久暂停。存档失败与局面恢复成功分开处理，并显示“波次已恢复，但存档失败”。

## 手工验收

1. 从第一波起正常开打，到多波后点击回到上波，检查确认框中的目标波号。
2. 分别在开波前和波内建造、升级、出售塔，改变金币或漏怪伤害后确认回退，对照当时开波前的状态。
3. 不点击开始，继续逐波回退至第一波准备态；按钮此时应禁用，波号不能小于 1。
4. 回退后重新布防并开始，分别使用重试本波与回到上波；确认新布防状态被正确记录，金币与统计不重复累计。
5. 分别在暂停、两波之间的倒计时、切关以及三语言和手机安全区下核对确认/取消与点击区域。
