# 波次回退历史持久化（2026-11-10）

本次实现用户要求：停止运行、重新启动或退出后重新进入同一关，仍可恢复本局开波历史并连续回退。本文取代 2026-11-07 两份报告中的“历史只保存在内存、退出清空”说明。

工程为 `D:/FreedomTower_1`，Unity `2022.3.62f3c1`，MCP 插件 `v10.3.0`。使用用户当次确认的 stdio / 6400，服务名 `unityMCP`，逐次选择 `FreedomTower_1@520e2c6d` 并核对 `project/info`。未扫描、猜测或修改端口；这些标识仅作本次连接线索。

## 当前行为

- 每次正式开波前保存该波完整起点，包括正式波次游标、塔阵及投入、金币和小数余数、生命、累计击杀/漏怪、逐波账目、战斗/关卡计时及启动标记、塔的战斗相位与注册顺序。
- 当前进度与本局历史存入原有加密 `layout/campaign` 的同一个 KV 值。SQLite 使用单行替换，JSON 使用文件替换，不分两次写入进度和历史。没有使用旧 `level_snapshot`，没有升级 SQLite schema 或让旧阵型记录整体失效。
- 过波后保存下一波准备态及历史。战斗中卖塔仍保存原开波边界，避免交易返还、伤害或半波收入与已完成账目混写。
- 回退后先删除目标波之后的内存历史，再把目标边界与保留历史一起落盘。重新布防开打会替换该波记录，旧分支不会在下次启动时复活。
- `TeardownLevel` 只释放内存；同一关重新读取自己的历史。其它关的历史保留且不会被引用到当前关。
- 显式重新开始整关会立即保存新局初始边界并替换该关旧局/历史，即使尚未开始第一波就停止运行也不会读回旧局。通关后重玩记录不带已结算局的回退历史。
- 最低边界仍是第一波第一次开打前的局面：开打前已布置的塔会保留在该检查点，关卡计时恢复为当时的未开始状态；不能回退到更早的不存在记录。

## 完整性与失败处理

读取历史时先整体校验，再接管：历史版本、关卡、runId、配置内容签名、正式 roundId 列表、游标范围、重复/未来检查点、完整已完成波次账目和当前局的相同前缀，以及塔配置、格位、相位数量和有效性都必须匹配。

金币余数、计时启动标记及重复计时字段必须一致；`NaN`、无穷大和不匹配计时均不能用于回退。无效历史被忽略并记录警告，已有有效当前进度继续读取。原存档没有历史时不推造旧检查点；继续游玩后，新捕获的连续后缀可以持久化使用，遇到缺失历史即停止向前回退。

写入后回读完整 KV 内容，避免后端吞掉 IO 异常后误报成功。写失败保留旧磁盘记录；运行中的恢复可以成功，但会显示现有多语言提示“波次已恢复，但存档失败”。此时重新启动会读取上次成功保存的状态，不能承诺失败的新操作已落盘。
