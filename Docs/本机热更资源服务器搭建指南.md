# 本机热更资源服务器搭建指南

> **这份文档要解决的问题**：在**不买服务器、不租云主机**的前提下，用你自己这台电脑
> 当一个"资源服务器"，让安卓真机上的 APK 能连上来下载热更资源（AB 资源包 + 热更 dll），
> 从而验证整条热更链路是否真的通了。
>
> 适用对象：**第一次接触这块、不熟悉网络概念**的人。所以下面每一步都写得很细。

---

## 〇、先纠正一个常见误解：WinSCP 用不上

你之前提到已经装了 **WinSCP**。这里要说明白：**做本机测试不需要 WinSCP。**

| 工具 | 它是干什么的 | 本机测试需要吗 |
|---|---|---|
| **WinSCP** | 一个"**上传客户端**"—— 把文件从你电脑传到**远处的一台服务器**（比如阿里云主机），靠的是 SFTP/SCP 协议 | ❌ **不需要**。本机测试根本没有"远处的主机"，服务器就是本机 |
| **Python http.server** | 一个"**服务器程序**"—— 让别人（手机）能**访问**你电脑上的某个文件夹 | ✅ **这才是要用的** |

一句话：**WinSCP 负责"把货送到远方仓库"，而本机测试是"货就在自己家，直接开门给人看"。**
等将来真要部署到云主机时，WinSCP 才会派上用场（那时用它把 `ServerRoot/` 传上去）。

## 一、整体原理（先看懂这张图，后面每一步就都顺了）

```
┌───────────────────────┐              ┌───────────────────────┐
│   你的电脑            │              │   安卓手机            │
│                       │              │                       │
│  ┌─────────────────┐  │   同一个     │  ┌─────────────────┐  │
│  │ Python          │  │   WiFi/热点  │  │ 《自由人塔防》  │  │
│  │ http.server     │◄─┼──────────────┼──┤ APK             │  │
│  │ 监听 8000 端口  │  │              │  │                 │  │
│  └────────┬────────┘  │              │  └─────────────────┘  │
│           │ 读        │              │         │ 要资源      │
│  ┌────────▼────────┐  │              │         │             │
│  │  ServerRoot/    │  │              │         │             │
│  │   目录          │  │              │         │             │
│  └─────────────────┘  │              │         │             │
└───────────────────────┘              └───────────────────────┘
       192.168.43.100                        手机访问
                                              http://192.168.43.100:8000/...
```

三个关键点：

1. **手机和电脑必须在同一个局域网里**（连同一个 WiFi，或手机开热点给电脑连）。
   否则手机的请求根本到不了你电脑。
2. **手机访问的是你电脑的局域网 IP**（形如 `192.168.x.x`），**不是** `localhost`。
   `localhost` 在手机上的意思是"手机自己"，它自己身上没有那个服务器。
3. **热更资源要放在一个固定的目录结构里**，服务器只负责把这个目录"暴露"出去。
   下一节讲这个目录长什么样。

---

## 二、服务器上必须长成这个目录结构

这是**整件事最容易出错的地方**，所以单独讲。

YooAsset 和人手写的 dll 下载器，都会按**约定好的相对路径**去请求文件。服务器上的目录必须严格对上：

```
ServerRoot/                          ← 服务器根目录（http.server 指向它）
└── Android/                         ← ① 平台名（YooAsset 用 BuildTarget 名字，固定是 "Android"）
    ├── FreeTower/                   ← ② 包裹名（= YooAsset 收集器里建的包裹名，固定 "FreeTower"）
    │   └── 1.0.0/                   ← ③ 版本号（= 构建时填的「资源包版本」）
    │       ├── FreeTower.version          ← 版本号文件（内容就一行：1.0.0）
    │       ├── FreeTower_1.0.0.bytes      ← 资源清单
    │       ├── FreeTower_1.0.0.hash       ← 清单哈希
    │       ├── *.bundle ×N                ← 所有 AB 资源包
    │       └── ...
    └── HybridCLR/                   ← ④ 热更 dll 目录（**与 ①②③ 平级，不在版本目录里**）
        ├── FTProject.Runtime.dll
        ├── FTProject.Gen.dll
        ├── FTProject.LubanLib.dll
        ├── FTProject.ThirdParty.Reporter.dll
        ├── FTProject.ThirdParty.SuperScrollView.dll
        ├── System.Core.dll                    ← 以下 6 个是 AOT 补充元数据
        ├── UnityEngine.AssetBundleModule.dll
        ├── UnityEngine.CoreModule.dll
        ├── UnityEngine.JSONSerializeModule.dll
        ├── YooAsset.dll
        └── mscorlib.dll
```

对应到手机实际发出的请求地址：

| 手机要的东西 | 它请求的完整地址 |
|---|---|
| AB 版本号 | `http://192.168.43.100:8000/Android/FreeTower/1.0.0/FreeTower.version` |
| 资源清单 | `http://192.168.43.100:8000/Android/FreeTower/1.0.0/FreeTower_1.0.0.bytes` |
| 某个 AB 包 | `http://192.168.43.100:8000/Android/FreeTower/1.0.0/<哈希>.bundle` |
| 热更 dll | `http://192.168.43.100:8000/Android/HybridCLR/FTProject.Runtime.dll` |

⚠️ **两个最容易搞错的点**：

1. **热更 dll 不在版本目录里。** 它在 `Android/HybridCLR/`，与 `Android/FreeTower/` 平级。
   原因见代码注释：dll 走的是**独立下载通道**（不能依赖 YooAsset，因为 dll 要更早加载），
   而 AB 走 YooAsset。两条通道各有各的目录约定。
2. **`ResServerConfig.ServerUrl` 只写到端口，不写平台段。**
   平台段（`Android/FreeTower/1.0.0/`）是**程序自动拼的**。
   你要是手写进配置，就会变成 `.../Android/Android/FreeTower/...` → 404。

## 三、手把手操作步骤

### 步骤 1：确认本机局域网 IP

**目的**：知道手机该往哪个地址发请求。

在电脑上开 `cmd`（开始菜单搜 "cmd"），敲：

```cmd
ipconfig
```

在输出里找 **无线局域网适配器 WLAN** 那一段，看它下面的 **IPv4 地址**：

```
无线局域网适配器 WLAN:
   ...
   IPv4 地址 . . . . . . . . . . . . : 192.168.43.100     ← 就是这个
```

⚠️ **这个地址会变**：换了 WiFi、重启路由器、重连热点，它都可能变成别的值。
每次测试前最好确认一遍。本工程当前写入代码里的值就是 **`192.168.43.100`**。

> 如果你电脑连的是网线而不是 WiFi，就看 **以太网适配器** 那段的 IPv4 地址。

### 步骤 2：确认手机和电脑在同一个局域网

最简单的判断：**手机和电脑连的是同一个 WiFi 名字**（或电脑连的是手机开的热点）。

⚠️ 注意这些**会失败**的情况：
- 手机用 4G/5G 流量，电脑用 WiFi → **不同网络，不通**
- 电脑连的是"访客 WiFi"、手机连的是主 WiFi → 很多路由器会**隔离访客网络**，不通
- 公司/学校 WiFi 开了"客户端隔离"（AP isolation）→ **同 WiFi 也互相不通**

### 步骤 3：确认代码里的服务器地址正确

打开 `Assets/Scripts/Core/Res/ResServerConfig.cs`，确认这一行是你的实际 IP：

```csharp
public const string ServerUrl = "http://192.168.43.100:8000";
```

⚠️ **这个地址在工程里有两份，必须一致**：

| 位置 | 变量 | 为什么有两份 |
|---|---|---|
| `Assets/Scripts/Core/Res/ResServerConfig.cs` | `ServerUrl` | 热更集里，管 **AB 资源** 的地址 |
| `Assets/AOTAssembly/BootLoader.cs` | `ServerUrlForAOT` | AOT 集里，管 **热更 dll** 的地址 |

**为什么不能合并成一份**：HybridCLR 的铁律是"AOT 程序集不能引用热更程序集"。
`ResServerConfig` 在热更集（`FTProject.Runtime`）里，AOT 侧 `BootLoader` 引用它就等于违反铁律、
IL2CPP 打包会失败。所以只能各写一份常量。

> ✅ **好消息**：你**不用每次改代码重新打包**。程序启动时会优先读
> `persistentDataPath/server.txt` 这个文件里的地址来覆盖代码里的常量。
> 换 WiFi 导致 IP 变了时，只要往手机上那个文件里写一行新地址即可（见步骤 7 的排错部分）。

### 步骤 4：把热更产物拷到 ServerRoot

本工程已经准备好一个脚本，一条命令搞定：

```bash
bash Tools/sync_to_server.sh Android 1.0.0
```

它做两件事：
1. `Bundles/Android/FreeTower/1.0.0/` → `ServerRoot/Android/FreeTower/1.0.0/`
2. `Assets/StreamingAssets/HybridCLR/*.dll` → `ServerRoot/Android/HybridCLR/`

> **前提**：这两处的产物必须先存在。
> - `Bundles/...` 要跑过 Unity 菜单 `Tools ▸ 塔防 ▸ YooAsset 接入 ▸ 接入向导 ▸ ③ 构建真实资源包`
> - `Assets/StreamingAssets/HybridCLR/*.dll` 要跑过 Unity 菜单
>   `Tools ▸ 塔防 ▸ HybridCLR ▸ 1. 拷贝热更 dll 到 StreamingAssets`
>
> 脚本会自己检查，缺了会明确告诉你该跑哪个菜单。

**版本号要对上**：脚本第二个参数（`1.0.0`）必须与 Unity 构建时填的「资源包版本」一致。
不一致的话，手机请求的目录在服务器上不存在 → 404。

### 步骤 5：启动资源服务器

**双击这个文件即可**：

```
ServerRoot/启动资源服务器.bat
```

它会：
- 自动找到 Python（优先用 WorkBuddy 内置的，其次系统 `python`）
- 自动探测本机局域网 IP 并打印出来
- 启动 `http.server`，把 `ServerRoot/` 目录暴露在 **8000** 端口

启动成功后，窗口里会显示类似：

```
  资源根目录 : D:\FreedomTower_1\ServerRoot\
  访问地址   : http://192.168.43.100:8000
  服务端口   : 8000
   ...
127.0.0.1 - - [11/Oct/2026 11:23:45] "GET /Android/FreeTower/1.0.0/FreeTower.version HTTP/1.1" 200 -
```

**这个窗口不要关**，关了服务就停了。停止服务 = 关窗口 或 按 `Ctrl+C`。

> **首次运行会弹防火墙提示** → 勾选 **"专用网络"** 并点 **"允许访问"**。
> 不点允许的话，手机连不上（Windows 默认拦截入站连接）。

> **想用命令行手敲**（不想用 bat）：
> ```bash
> python -m http.server 8000 --directory ServerRoot --bind 0.0.0.0
> ```
> `--bind 0.0.0.0` 的意思是"接受来自任何网卡的连接"，这是手机能连上的关键。
> 如果只写 `--bind 127.0.0.1`，那就**只有本机能访问**，手机一定连不上。

### 步骤 6：先用手机浏览器验证"通不通"

**这一步非常重要**，能立刻区分"是网络不通"还是"是游戏代码的问题"。

手机连上同一个 WiFi 后，用**手机浏览器**打开：

```
http://192.168.43.100:8000/Android/FreeTower/1.0.0/FreeTower.version
```

| 你看到的 | 说明 | 下一步 |
|---|---|---|
| 页面显示一行 `1.0.0` | ✅ **链路完全通了** | 进步骤 7 |
| 转圈很久然后"无法访问" | ❌ 网络层不通（防火墙 / 不同网段 / IP 写错） | 见下面排错表 |
| 显示 404 页面 | ⚠️ 通了，但**目录结构不对** | 检查 `ServerRoot` 里的路径层级 |

顺便也可以打开这个地址，应该看到一列 `.bundle` 文件名：
```
http://192.168.43.100:8000/Android/FreeTower/1.0.0/
```

### 步骤 7：让 APK 走热更

这一步的前提是 **APK 里已经开了热更宏**。按顺序做：

1. **打开热更宏**：Unity 菜单 `Tools ▸ 塔防 ▸ YooAsset 接入 ▸ 3. 启用 FT_HOTUPDATE 宏（真机热更）`
   - 它会把这个宏写到 Standalone / Android / iOS / WebGL **四个平台组**
     （编译宏是按平台存的，只加当前平台的话，换平台出包会静默失效）
   - 同时确认 `USE_YOOASSET` 宏也是开着的（菜单 `1. 启用 USE_YOOASSET 宏`）
2. **确认地址**：`ResServerConfig.ServerUrl` = 你的实际 IP（步骤 3）
3. **打 APK**：正常的 Android 构建出包、装到手机
4. **看日志**：手机连电脑用 `adb logcat`，或游戏内 Reporter 面板，找这些标签：

```
[Boot] 正在准备热更程序集…
[Boot] 同步热更 dll 3/11           ← dll 通道在工作
[HotUpdate] dll 已更新：FTProject.Runtime.dll（323072 字节）
[Res] 热更已启用。服务器根地址 = http://192.168.43.100:8000
[Res] 发现新资源版本：1.0.0 → 1.0.1，开始更新。
[Res] 热更新完成，共下载 N 个文件。
```

## 四、完整验证流程（想确认"热更真的生效了"）

只跑通"能连上"还不够 —— 要证明**新资源真的被下下来并被使用了**，用这个流程：

1. **出首包**：先把 `ResServerConfig.EnableHotUpdate` 改成 `false`，构建 APK（首包自带完整资源，
   这样即使没网也能进游戏），装到手机，确认能正常玩。
2. **改点东西**：比如改个塔的攻击力、改句提示文案（**改的是热更集里的代码/资源**）。
3. **重新构建并提到新版本号**：Unity 菜单 `接入向导 ▸ ③ 构建真实资源包`，
   把「资源包版本」改成 `1.0.1`（**必须换号** —— 同一个版本号构建第二次 YooAsset 会直接报
   `ErrorCode115: Package output directory exists`）。
4. **同步到服务器**：
   ```bash
   bash Tools/sync_to_server.sh Android 1.0.1
   ```
   （旧版本目录 `1.0.0` 留着，这样能验证"差异下载"而不是全量下载）
5. **如果改的是代码**，还要跑 `Tools ▸ 塔防 ▸ HybridCLR ▸ 1. 拷贝热更 dll 到 StreamingAssets`，
   再同步一次 dll。
6. **重开 APK**：这次把 `EnableHotUpdate` 改回 `true` 重新出包？**不用** ——
   更简单的做法是**直接用 server.txt 覆盖**（见下），或者就用已经开了热更的那版 APK。
7. **观察**：启动时日志应出现 `发现新资源版本：1.0.0 → 1.0.1` + 下载进度条；
   进游戏后确认改动**确实生效了**。

### 用 server.txt 免重打包换地址（很实用）

程序启动时会读手机可写目录下的 `server.txt`，优先级**高于**代码常量：

```
路径：/storage/emulated/0/Android/data/com.lzyfreedomtower.freedomtower/files/server.txt
内容：http://192.168.43.100:8000        （就一行；以 # 开头的行会被当注释跳过）
```

手机换 WiFi 导致 IP 变了时，用 adb 推一下就行，**不用重新打包**：

```bash
adb push server.txt /sdcard/Android/data/com.lzyfreedomtower.freedomtower/files/server.txt
```

## 五、排错速查表

| 症状 | 最可能的原因 | 怎么查 / 怎么修 |
|---|---|---|
| 手机浏览器打不开那个 `FreeTower.version` 地址 | ① 防火墙没放行 ② 不是同一 WiFi ③ IP 写错 ④ 服务没起 | ① 看 Windows 防火墙提示有没有点"允许"；② 手机和电脑连同一个 WiFi；③ 重新 `ipconfig` 确认；④ 看 bat 窗口有没有报错 |
| 电脑本机能打开 `http://127.0.0.1:8000/...`，手机打不开 | `--bind 127.0.0.1` 了（只监听本机回环） | 必须 `--bind 0.0.0.0`；脚本里已经是 0.0.0.0 |
| 手机显示 404 | 目录层级不对，或版本号不对 | 对照第二节的结构逐级核对；确认 `FreeTower.version` 在 `Android/FreeTower/<版本>/` 里，**不是**在 `Android/` 里 |
| 游戏里报 `Active package manifest not found.` | 版本目录里缺 `FreeTower_1.0.0.bytes`（清单没传全） | 整个版本目录一起拷，别只挑 `.bundle` |
| 报 `热点/防火墙` 相关错误，但浏览器能开 | 浏览器请求的是普通网页；游戏的 UnityWebRequest 可能被明文 HTTP 策略挡下 | 本工程 `insecureHttpOption: 2`（AlwaysAllowed）已放行，正常不会遇到；若怀疑被动过，见第六节复核方法 |
| dll 下载日志显示 `404`，但 AB 能下 | `Android/HybridCLR/` 目录漏了或 dll 没拷全 | 跑 `Tools/sync_to_server.sh`，它会一并同步 dll（同步 11 个）|
| 改了资源但游戏里没变化 | 版本号没换，或 APK 没开 `FT_HOTUPDATE` 宏 | ① 版本号必须递增（同版本号构建会报 ErrorCode115）；② 检查宏状态菜单 `0. 查看宏状态` |
| 端口 8000 被占用 | 别的程序占了 | 换个端口启动（如 8080），并同步改 `ResServerConfig.ServerUrl` 和 `BootLoader.ServerUrlForAOT` |

## 六、几个必须知道的技术前提

### ✅ Android 明文流量：本工程已正确配置，不用改

本工程的资源服务器是 `http://`（明文），而 Android 从某个版本起会限制明文 HTTP。
**这一项已经确认配好了**，无需你做任何事。证据如下：

Unity 用一个叫 `InsecureHttpOption` 的设置控制这件事，它的取值（来自 Unity 官方源码
`Editor/Mono/PlayerSettings.bindings.cs`）：

```csharp
public enum InsecureHttpOption
{
    NotAllowed      = 0,   // 禁止明文 HTTP
    DevelopmentOnly = 1,   // 仅开发版允许
    AlwaysAllowed   = 2,   // 始终允许  ← 本工程用的是这个
}
```

而本工程 `ProjectSettings/ProjectSettings.asset` 里是：

```
insecureHttpOption: 2
```

→ 即 **`AlwaysAllowed`**，UnityWebRequest 可以用明文 HTTP。**不需要改 AndroidManifest。**

> 📌 **复核方法**（将来若怀疑它被动过）：
> 菜单 `Edit ▸ Project Settings ▸ Player ▸ Other Settings`，
> 找 **Allow downloads over HTTP** 这一项，确认是 **"Always allowed"**。
> 取值对照：`Not allowed / In development builds only / Always allowed`。
> 或者直接看 `ProjectSettings/ProjectSettings.asset` 里 `insecureHttpOption` 的值必须 = `2`。

> ⚠️ **只用于开发测试**。正式上线应改用 `https://`，届时可把这项调回
> `DevelopmentOnly` 或 `NotAllowed` 收紧安全面。

### ✅ INTERNET 权限：会自动加上，不用手工配置

Android 联网需要 `android.permission.INTERNET` 权限。本工程**不需要手工加**，理由：

- `ProjectSettings.asset` 里 `ForceInternetPermission: 0`（不强制），
  Unity 在 Android 平台会**自动扫描代码**，只要发现用了网络 API 就自动加入该权限；
- 本工程 AOT 侧（`HotUpdateDllDownloader.cs`、`HotUpdateAssembler.cs`）与热更侧
  都明显使用了 `UnityWebRequest`，Unity 一定会自动加上。

> 📌 **复核方法**：APK 构建后，用 Android Studio 的 APK Analyzer 或
> `aapt dump permissions your.apk` 查看，应有一行
> `uses-permission: name='android.permission.INTERNET'`。
> 若真的缺了，再在 `ProjectSettings ▸ Player ▸ Android ▸ Other Settings` 里
> 勾选 **"Requires Internet"**，把 `ForceInternetPermission` 变成 `1`。

### ⚠️ 首包必须自带资源

`ResServerConfig.EnableHotUpdate` 的注释里写了这条：**首包务必让 `EnableHotUpdate = false`**。

理由：如果首包资源是空的、同时又开了热更比对，那么一旦服务器连不上（用户在外面、断了网），
**新装的玩家完全玩不了**。正确的形态是"首包自带一份完整资源 + 启动时比对热更"，
这样最坏情况也只是玩到旧版本。

### ⚠️ 这是"开发测试用"的服务器，不适合上线

`python -m http.server` 是单线程的简单服务器，**没有**并发能力、断点续传、CDN 加速、鉴权。
用作本机验证完全够，但**正式上线必须换成正经的静态文件服务**：

| 场景 | 建议 |
|---|---|
| 本机测试（本文档） | `python -m http.server` ✅ |
| 内网小规模测试 | Nginx / Caddy 静态目录 |
| 正式上线 | 对象存储（OSS/COS）+ CDN，或云主机 + Nginx |

## 八、一句话总结

**本机测试热更 = 三个条件同时满足：**

1. **手机和电脑同一个 WiFi**（网络通）
2. **`ServerRoot/` 目录结构对**（路径通）
3. **APK 开了 `FT_HOTUPDATE` 宏、地址指向本机 IP**（代码通）

缺任何一个都会失败，而用"手机浏览器打开 `FreeTower.version` 地址"这一步，
就能最快地把问题定位到是哪一层坏了。
