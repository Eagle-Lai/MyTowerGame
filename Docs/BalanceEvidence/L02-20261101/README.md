## 2. L02 原状：欠调 9 倍，不是「略易」

- 地图 16×9=144 格，S=(4,0)，E=(4,15)，零障碍零禁建，可拉满蛇形。
- 原值：N 32→176（Σ2,600），EHP 282→55,693，末波 EHP **只有 L01 的 1/9**；25 波 desc 全是 `manual: L1-scaled`。

## 3. 设计模型（每个数可复算）

设 L01 下标 1、L02 下标 2：

| 量 | 关系 | 取值 | 依据 |
|---|---|---|---|
| 路径比 E | 72 / 43 | **1.67** | `balance_capacity.mjs --spacing 2` 实测 |
| 参考驻军塔数 | 59 / 33 | **1.79** | 同上 |
| 单塔有效覆盖 | 6.02 / 5.61 格 | **1.07** | `capacity_calc.py`（射程内路径弧长） |
| **容量比** | 355.4 / 185.2 | **1.92** | 参考驻军口径 |
| 金币比 | 玩家能铺的塔数比 | **1.50** | 40 塔→60 塔（≈59 参考槽） |
| **EHP 比** | 金币比 × 单塔覆盖比 | **1.60** | 与 1.5 金币比自洽 |
| 数量比 | 峰值存活约束 | **0.69** | 见下 |

**为什么怪数要减少 40%**：峰值存活 ≈ (N/窗口)×通过时间，引擎上限 `maxEnemyAlive=200`。
路径长 1.67 倍 → 单只通过时间 41s→68s；若 N 不变，峰值存活会从 ~172 冲到 ~287 撞上限被限流。
取 N×0.69、窗口×1.15 后，峰值存活回到 ~170（与 L01 持平），画面密度与 L01 一致。

**为什么单体变厚**：同样的塔要打更久（+67%）才死，单体 HP 从 654 → 1,517（×2.32）。

## 7. 已知局限（必须如实记录）

- `balance_sim.mjs` 的 AI 是「参考驻军」而非最优玩家：开局即升级、按槽位轮换买冰霜塔（0 输出），
  **用现配置跑 L01 也会在 W5 崩**（16 塔 / 漏 10）。因此它只能做「同策略相对比较」，不能当绝对判据。
- 相对比较结果：同样 `--towerPowerScale 2.0` 下 L01 清到 R9、L02 清到 R7（EHP×1.6 时）。
  即模型认为 L02 仍略紧 1~2 波；考虑到参考驻军在 16×9 上单塔覆盖下降（塔位更分散），
  这一偏差方向与「大地图塔位摊薄」一致，已在 EHP 比里按 1.60（而非几何上限 1.92）留了余量。
- 真机手感仍需一次实机通关验证（本机未做完整 L02 手打）。
