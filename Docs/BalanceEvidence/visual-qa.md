## 数值候选的人工判读

血条与身体 `SpriteRenderer.bounds` 的纵向间距为负并不等同于压住可见身体。EvilEye、Bat、MohawkBat、Rat、GreenParasite、Tiger、RatKing 身体图及 RatKing 四方向图均实际检查了可见像素，血条与头顶、皇冠或翅膀仍分离。由透明边界触发的这些候选无需人为抬高血条。

Dreadnought 四方向动画测得最大边为 3.253—3.629 格。其中上方向展开武器时 3.629，右方向 3.540。静态规范目标约 3.2—3.5 格，动画姿态有小幅变化；图中身体、武器和血条完整，无异常遮挡。BodyRadius 仍是 0.6，没有引入多格碰撞或临时推挤。此观察接受为动画姿态差异，不将代表静态尺寸误写成所有动画帧的硬上限。

## 实际发现与修复复核

1. BugQueen 周围曾出现不透明洋红方块，属于实际画面异常。战斗 prefab 的 `Particles/ParticleSystemRenderer` 引用材质 GUID `5b340548b5ffd5448b73c5b81cafdf95`，本工程找不到对应材质定义；MossQueen 相关 prefab 也引用同一丢失材质。已补充存在的 `Assets/Materials/EnemyParticles.mat`，重拍实际运行图后目检通过，粒子仍启用。
2. M1 的 1024×768 初图中，速度按钮曾覆盖第一座塔按钮。`HudView` 已按实际安全区画布宽度计算两者间距，在不足 24 逻辑像素时整体右移三座塔按钮，16:9 原位置不变。新增底部五按钮两两矩形重叠、出画和中心射线归属探针，两分辨率实际复核全部通过。

3. 详情页曾无条件使用“时间基准待验证”，与最终 D04 的 `verified_unity_reference` 状态矛盾。已按实际校准状态显示提示；修复后重新生成 24 张 UI 图，英文、简体、繁体的两分辨率详情图均不再显示待验证提示，五星目标和计时范围说明仍完整。当前存档尚无本版本成绩时的“本版待评定”表示玩家成绩状态，与时间基准校准状态分开。

修复前的真实异常截图保留在 [VisualBefore](VisualBefore/)；这些图只记录发现过程，不代表最终画面。

## 证据边界

UI 结算数据由唯一评分器生成，是实际 prefab/View/字体的合成测试场景，只认证显示行为，不认证这组成绩通过实际玩法达成。怪物图是真实运行预制体的隔离半血样例，修改半血只作用于未注册克隆，不通过 Hurt 伪造实战统计。M1 探针读取真实相机投影和 EventSystem 射线，没有模拟点击建塔。实战通关、经济合法性和五星可达性使用独立 PlayMode 回放证据。

本轮覆盖桌面 GameView 的 16:9 与 4:3；移动设备安全区、触控、拖拽与实际设备性能不由这些截图单独认证。
