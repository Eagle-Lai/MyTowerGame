## 五、必须同步维护的工程链路

### 5.1 UI脚本、预制体与构建器

当前主要页面为 MainMenuView、SelectView、SelectLevelItemView、LevelDetailView、GameIntroView、HudView、TowerInfoView、PauseView、TipsView、TowerCodexView、TowerCodexItem、SellConfirmView、ConfirmView、SettingView、LevelClearView，以及 SplashView、LoadingView、AOT HotUpdateView。

当前大量节点通过 transform.Find 的路径绑定。改层级或节点名时，脚本查找、序列化引用、事件监听、预制体和构建器必须同批同步，不保留“找不到时忽略”而造成按钮静默失效。新增引用优先清晰显式绑定，不在每帧查找整树。

必须特别检查：

- UIPrefabBuilder 的页面生成方法和UI资产路径。
- UISkinArtGenerator 是否会把新皮肤覆盖成旧皮肤。
- UIResolutionLayout、UIResponsivePage、UIFitInParent 是否会在导入或运行时把新布局重新排回旧版。
- SelectView、TowerCodexView 与 SuperScrollView 的初始化、尺寸缓存、条目池和选中逻辑。
- 旧的“点旁边卡片→自动居中→自动进入关卡”不能继续支配新设计的网格选关；本轮应改成点选更新预览，再明确查看简报/开始，避免误进关。
- MainMenuView 的运行时颜色与文本刷新不能覆盖新令牌。
- 新怪物图鉴不能只有 ResTable 登记而缺少实际脚本、预制体和可达入口。

先读清构建器会写哪些资产，再执行必要的定点入口；不要直接运行全项目总搭建。若全量UI重建确有必要，先确认它只触及本轮UI资产且已保留所需引用；同步更新生成规则，使以后重建不会退回旧样式。

### 5.2 真实入口与资源加载

沿 BootLoader/HotUpdateEntry → Main 场景 → GameSceneLauncher/GameFlowManager → UIManager → ResLoader/ResTable 核对实际加载链，而不是在孤立场景里放一份新UI就结束。

当前代码中UI层为 UICanvas 下的 BgPanel、NormalPanel、TipsPanel。保留或有目的地调整分层，同时保证模态遮罩、Raycast、焦点和返回正确；装饰图不能吞掉战场触摸。

需要保留的资源边界：

- HotUpdateView 是APK内可用的AOT启动壳，位于 Assets/Resources/BootUI/，不能依赖尚未下载的热更DLL或热更字体/材质。
- SplashView、LoadingView 当前位于 Assets/HotUpdateUI/，通过已验证的活动资源版本加载；不能照旧注释把它们随意挪回Resources。
- 新UI图像/字体/材质必须随正确资源组进入现有加载路径。不能编辑器靠AssetDatabase直读可见，运行包中却找不到。
- ResTable.cs、ResBundle相关定义、Assets/BundleCollectorSetting.asset、Assets/Editor/YooAsset/FTYooAssetSetupWizard.cs按实际依赖最小同步，保持资源逻辑名、路径、资产类型一致。
- 不把整个Assets、Docs设计包或临时生成目录加入收集器；不把敌人资源错误打入UI组。
- 需要更新本地模拟资源信息时使用现有工具和目标平台；不自动发布远端热更、不改服务器地址、不用清空全部缓存回避版本问题。
- 加载、实例化、关闭、复用与销毁需遵守当前句柄释放方式，不泄漏实例、图像、材质或异步回调。

### 5.3 真实数据与交互

- 通过现有 Configs、PlayerDataManager、SaveManager、GameFlowManager、GameClock、LevelClearInfo、RatingPresentation 和事件接口取得数据，执行前核对真实接口。
- 当前 LevelClearInfo 已有 victory、stars、ratingResult、progressSaved、savePending、previousBest、newRecord、hp、maxHp、killed、leaked、nextLevelId、hasNext。沿用这些语义，不在UI内重新计算评分。
- 当前 GameFlowManager 已有 RetryPendingClearSave，保存重试连接现有流程，不另造一条“显示成功但未保存”的捷径。
- 保留点塔型后点地块与现有 TowerDragButton/HudView 手势能力；在现有合法性判定上呈现点按和拖动反馈，避免一次松手触发两次建造、重复扣款或点穿UI。
- 倍速显示当前实际档位并调用原有接口；不要把设计中仅示×1误写成删除已有档位，也不要凭设计增加未知档位。

## 八、语言、字体、比例与性能

### 8.1 三语与字体

- 所有静态、动态、提示、按钮、图鉴、确认、保存错误和启动阶段支持简中/繁中/英文。
- 复用 LanguageManager、Localization、TextLocalizer、BootLocalization 的职责，启动AOT文案与正式运行文案各走合法来源。
- 设计稿的Microsoft YaHei/Arial是制图字体，不代表可自动打包Windows字体。使用有明确授权、可覆盖目标字形的无衬线字体与TMP资源，并保留许可说明；不能默认继续用现有衬线字体达到新稿观感。
- 字体资产、fallback、材质和启动依赖同样进入正确资源组；中文、繁体、英文、数字与符号不出现方框、丢字或未下载字体。
- 保留字级。英文长按钮优先容器重排、合理短文案和拆行，不把全页统一缩成小字。实际最大金币、价格、关卡名、用时和错误长度纳入布局。
- 数值与单位紧邻，字段与数值对齐；状态不只依赖颜色，语言选择有明确勾选。

### 8.2 比例和安全区

- 主基准1920×1080横屏，同时覆盖1280×720、1024×768、2340×1080、2560×1080。
- 重点对照适配稿的选关、详情、选中塔HUD、结算；全部普通弹窗和三语也要在这些比例下完整。
- 使用实际Screen.safeArea，经正确坐标转换后作用于内容层；背景和模态遮罩可全屏。不要嵌套重复收缩安全区，不把安全区组件挂到被Canvas反复驱动的根而假装生效。
- 设计中的左右96、上24、下36仅为压力值，不能硬编码为所有设备的真实Insets。
- 窄屏优先改变列数和面板排布，超宽合理使用侧栏，不能只靠整体缩放。入口、基地、主要敌群和所选塔保持可见；当前可用操作完整。
- 点击热区按实际设备密度核对，关键操作目标至少48dp并留间距；不能用设计图像素直接声称达到dp标准。
- 尊重已有系统返回、暂停与来源页面，遮罩不点穿，非交互装饰关闭Raycast，焦点不落在危险默认项。

### 8.3 移动端与生命周期

- 复用图集、共享材质与轻量过渡，避免多层大面积半透明和持续Canvas重建。
- 动态数值按事件或必要频率更新；不在每帧执行资源加载、全树查找、字体重建和无意义字符串拼接。
- UI动画在暂停下仍可正常完成，合理使用不受战斗timeScale影响的时间；关闭时停止动画并恢复输入，不残留Tween/协程/回调。
- 复用弹窗与图鉴条目时重置选中、范围、按钮可用性、异步图像与监听状态，防止跨对象串数据。
- 不为UI工作升级Unity/UGUI/TMP/YooAsset/HybridCLR或安装新渲染管线；确有依赖缺口先找当前版本可行方案。
