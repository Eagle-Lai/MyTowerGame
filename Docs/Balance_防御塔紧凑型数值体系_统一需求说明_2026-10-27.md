## 2. 分析流程与复现要求

### 2.1 推荐执行顺序

章节是交付结构，不等于执行次序。分析按以下依赖推进：

## 3. 需求 A：三类塔 × 三级数值

### 3.1 九行必需字段

九行按当前 TowerInfo.xlsx 和 tbtowerinfo schema 输出，不新增塔种、等级或升级链。字段名以实际 schema 为准。

| 字段 | 要求 |
|---|---|
| 塔种、等级、upgradeTo | 显示三塔分工和现有升级链；保持结构，不新增塔种 |
| power | 普通/火力塔的整数单发伤害逐级递增；减速塔恒为 0，不要求伤害单调增长 |
| CD | 毫秒；攻击塔攻击间隔逐级递减；减速塔按光环脉冲周期解释，说明级间变化及实际覆盖收益 |
| radius | 攻击/覆盖半径逐级递增，标格数及源字段精度；radius 为浮点字段，不得先取整后分析 |
| aoe | 仅适用于火力塔；爆炸半径逐级递增，说明关联 bulletId 及字段来源 |
| effectValue | 仅适用于减速塔，配置定义域 0–1，逐级递增；另报运行时钳制上限及“取最强有效效果”规则 |
| prices | 建造价和各级升级增量价为整数，价格逐级递增，给出梯度及累计换算；不误写成累计费用 |
| 累计投入、sellPrice、真实退款 | 给公式；区分表字段卖价、累计成本、Global.sellRefundRate 后实际到账以及运行时取整 |
| searchIntervalMs、rotateSpeed、canAttackAir 等 | 对适用字段给数值；沿用须标注理由，修改须给影响范围，不适用写 N/A 并说明 |

如当前 30×25 基线继续使用“累计投入 × 70%，向下取整”生成 sellPrice，须在报告中明确写出公式，并把全局退款率造成的真实到账差异另列。退款率在同一版本采用一个全局定义，不得按关卡或塔行暗改。

必须列出累计投入 = 升级链各次 prices 之和。真实退款以当前代码为准；当前核对入口使用 max(0, RoundToInt(sellPrice × Global.sellRefundRate))，不得误写成“累计投入直接乘退款率”。取整方法和极端值处理均要复算。

### 3.2 逐字段取值理由

每个字段必须有可检验的数字理由，至少回答：

1. 建造价为何取该值，而非上下浮动 20%；上下浮动时哪些预设、关卡、波次首先改变通过状态或紧凑性。
2. 各级增量价格倍率为何如此，和伤害、覆盖或减速增量之间的关系是什么。
3. 升级每金有效产出 ÷ 新建每金有效产出是多少；为何产生此比例，不能只写“升级更划算”。
4. 三类塔建造阶段的有效产出差异是多少、控制范围如何论证；不得把减速塔硬算成伤害 DPS。
5. 减速塔价值用什么可复算指标衡量、公式和前提是什么。
6. 哪些字段是低敏感度参数、哪些是高杠杆参数；敏感度结论必须由实际扰动仿真或可复算依赖关系支持，不能只凭定性猜测。

### 3.3 成长曲线与塔间比较

每类塔的适用成长字段都须给出：

- 曲线族：线性、几何、凸、凹或其他明确定义的曲线，并说明选择理由。
- L2/L1、L3/L2、L3/L1 倍率表。
- 各级累计投入与每金有效产出。单体塔报告真实有效 DPS；火力塔报告有效 DPS 并说明仿真命中数；减速塔报告等效价值及其换算假设。
- 每金产出随等级递增或递减的方向和理由。
- 升级相对新建的拐点，以及受阵地密度、可用塔位、空地目标、路径变化和经济时点影响的触发条件。

普通和火力塔的理论 DPS = power / (CD/1000)，只用于属性比值；正式有效 DPS 须包含真实索敌、目标切换、冷却、护甲、AOE 命中和过量伤害。每金产出、升级效率、新建效率须给公式及单位，注明新建是否包含延长路径和新增空地覆盖的收益。

减速塔不得以 power=0 得出“价值为零”，也不得伪造成直接伤害塔。至少报告覆盖时长、被减速敌人秒数、地空对象及与不放该塔相比火力区有效伤害/击杀位置的变化，说明作用前提。脉冲间隔、持续时间和离圈余效分开报告；多塔重叠不相乘，弱减速是否能延长强减速、效果切换及运行时钳制均按当前 BaseEnemy 实现。

### 3.4 A 类验收

- 对适用字段执行表驱动的单调性断言；不适用字段为 N/A 并说明，不伪造单调性。
- 累计价、卖价、退款能由公式和运行时规则复算，与表格一致。
- 任一字段变化都能追踪到派生值和受影响的 profile × level × wave 结果。
- 上述六项数值理由均给出可量化回答。

## 4. 需求 B：地图布局、长路线和容量

### 4.1 固定术语和合法性

| 术语 | 必须写明 |
|---|---|
| S 型迂回 | 明确采用蛇形手指墙、螺旋或其他可复算构造；说明手指方向、间距、是否允许非均匀间距与斜向 |
| “最大” | 明确优化约束，包括通路连通、路径相对空场的长度要求、塔位覆盖等；不可只写“最大布局” |
| 塔数 | 墙体塔、参与路径塑形的塔、仅覆盖路线或空中航线的哨位塔分别统计 |
| 合法布局 | 使用工程当前的可建格、占格、不得封死路径、放置与重算规则；不得另造一套合法性定义 |
| W | 长路线优先参考布局的实际塔数，不等同几何容量，也不等同塔数最大解 |

### 4.2 三种标尺和正式优先级

逐关并列报告：

| 标尺 | 定义 | 用途 |
|---|---|---|
| 几何容量 C | B 为原始合法可建格；q 为 0/1 最短路求得的 S→E 至少需保留的可建格数；C=B−q。q 不等于路径总格数 | 固定占用比例分母；不以选定长路线的 W 重定义 C |
| 塔数最大解 | 在合法 S 型构造下使塔数最大 | 报告“能摆多少”，不是默认平衡最优 |
| 路径最长解 | 在合法构造下使地面敌人实际最短路径最长，并兼顾火力复用 | 本工程的正式布局优先方向 |

本工程采用长路线与火力复用优先。若路径最长解不是塔数最多解，必须报告塔数差、路径差、射击窗口差和原因。塔数最大解保留为比较项，不得取代长路线参考布局。

三标尺若恰好相同，复核定义、约束与实现，并给出一致的证据；不能为了预设“必须背离”而改结果。用单位塔位的路径贡献和单塔平均射击窗口解释布局取舍。

### 4.3 全关布局结果

每关至少报告：

- 地图尺寸、原始可建格 B、几何容量 C、ceil(0.85C) 的旧参考值。
- 长路线布局实际塔数 W、墙体塔和哨位塔数量、保留通路格数、起终点、起终点直线距离、空场最短路径、布局后实际 A* 路径。
- 塔数最大解与路径最长解，二者路径、塔量、火力覆盖与差异。
- 可按网格照摆的塔位坐标或字符图，区分墙、路径、起点、终点和塔。
- 每种塔对地面路径及空中直线路径的有效射击窗口、重复覆盖次数、攻击/减速贡献。
- 搜索算法、目标函数、地图输入 hash、种子、预算、合法性和最优性边界。
- 手指间距 1、2、3 格的塔量与实际路径长度敏感性，解释变化趋势。
- 可建容量显著低于中位数的关卡；可用“低于中位数 30%”作筛查线，并区分地图尺寸、起终点和障碍因素。

若沿用有限搜索目标函数，应逐项报告路径长度、重复覆盖塔数、参与塔数、负塔数的排序或权重。有限预算内最优只能称“预算内最好结果”，不能宣称数学全局最优。

路径计算必须采用当前运行时四向 A* 规则及平局顺序，长度以实际移动步/连续段计，不用希望敌人走的几何折线替代。相同输入和种子重跑应一致；逐关给复算命令。必须量化比较塔数最大布局与路径最长布局的单塔平均射击窗口及比值，并逐关指出 S 型布局上限异常偏低的原因。

若沿用 balance_maze.py，公开其字典序目标“实际路径长度 → 重复覆盖 → 参与塔位 → 较少无贡献塔”的具体实现及各层筛选；当前实现有固定半径采样近似，须以候选塔表实际半径和真实攻击记录再次复核。仅与空中航线射程圆相切，或只有几何交点，不算有效射击窗口。不得为占用率补建既不输出、不减速、也不阻断捷径的塔。

### 4.4 塔量对照

在几何容量 C 基础上定义整数取整方式、布局生成算法和合法性检查，完成 100%、70%、50% 及 100% 不升级四种对照。每种对照报告地图/路径、攻击输出、空地处理、击杀位置、漏怪、玩家 HP 和经济。若受 S 型结构或合法通路限制达不到目标塔数，记录目标、实际塔数和限制；若受资金限制无法在实战买满，记录为不可负担。不得靠开局免费满图把诊断配置冒充可玩施工轨迹。

另报长路线参考布局的实际 W 和占用率 W/C。满图、70%、50% 对照不强迫参考布局达到对应占用率，低于 ceil(0.85C) 不自动失败。

这四档是诊断试验，不是星级条件或正式评分规则。“半图必须死、满图才可能五星”只检验是否与结果相符；出现低塔数高表现等反例时照实保留，不得为满足假设而增删塔或改评价。

### 4.5 B 类验收

- 30 关逐关齐全；结果能用 D 盘只读命令复算。
- 几何容量、塔数最大、路径最长三标尺及正式优先级齐全。
- 布局图可在编辑器中重建并通过当前工程合法性判定。
- 塔数与路径长度背离时给出量化解释和反例。

## 5. 需求 C：敌人构成、波次和 EHP

### 5.1 分类及数量口径

- 空中/地面以运行时 EnemyConfig.IsFlying 为准；role 和 Type 是独立属性，不可替代 IsFlying。
- 若存在既非纯空中也非纯地面的对象，按实际运行时行为说明；不得默认以“总数减空军”隐藏第三类。
- 数量同时报告配置计划数、尝试出生数、实际成功出生数及差异原因。maxEnemyAlive 造成的延迟须计入；待出生队列不得丢失。
- 飞行怪数量以运行时 IsFlying=true 判定，按每个 profile × level × wave 统计计划数和实际成功出生数；role 名称不替代该判定。
- 种类同时报告 canonical 家族数与实际战斗变体 ID 数，并说明变体是否归入既有家族。
- role 按工程字典映射普通、虫群、快速、飞行、中型、重型、精英、首领等；空地与 role 是两个维度，一个单位不得在两维内重复计为多个单位。

### 5.2 统计交付

面向八档全覆盖，按 profileId + levelId + waveOrdinal 唯一索引，至少给出：

1. 按关汇总：总怪数、空中/地面数及数量占比、种类与变体数、总原始 HP/EHP、空中 EHP 及占比。
2. 按波明细：30×25 波的出生数量、空地数量/比例、IsFlying=true 飞行怪计划/实生数量及相对上一波的差值、role 数量、单体 HP 分布、该波 EHP、出怪间隔、收入和出生延迟。
3. 按 role 明细：每关、每档 role 权重和数量；每类 role 首次出现的关卡和波次。
4. 单独标记空中单位首次出现波、空中占比最高波、各压力峰值波；不得以全关均值代替末波或峰值。
5. 每个 profile 的第 25 波空地构成与空地 EHP。

按关实际数与 expectedEnemyCount 或波次配置总数不一致时解释差异。若某关之后不再引入新兵种，应明确报告“自第 N 关起不再引入新兵种”。空中数量占比和空中 EHP 占比必须分开。

除汇总统计外，所有八档的每关第 5–25 波飞行怪数量梯度都是编组约束，按下一节的公式逐个 profile × level 断言。

### 5.3 飞行怪逐波递增硬要求

对 D01–D08 每个预设、每一关分别检查，不能用同一关其他难度档的数据代替。定义 A(p,L,w) 为该预设、该关、第 w 波中所有运行时 IsFlying=true 单位的计划出生总数，跨不同飞行怪种类求和。此要求约束每波飞行怪总数量，不要求同一个 canonicalEnemyId 或同一变体贯穿全部波次；各飞行怪种类及其数量仍须分别报告。

每个 profile × level 必须满足：

~~~text
for w in 5..25:
    A(profile, level, w) >= 1

for w in 6..25:
    A(profile, level, w) > A(profile, level, w - 1)
~~~

即第 5 波至少 1 只飞行怪；从第 6 波到第 25 波，飞行怪总数逐波严格增加，不允许持平或回落。数量必须为整数，因此每次至少增加 1 只；不预设固定增量或固定增长公式，具体数量须经统一模型推导及仿真确定。该规则作用于全部八档、全部 30 关，不能只在某些关、某一难度或“整体趋势”上满足。

第 1–4 波可以出现飞行怪，本条不要求飞行怪只能在第 5 波首次登场，也不要求第 5 波数量大于第 4 波。第 1–4 波的构成仍按兵种解锁、教学和整体数值设计处理；新增的严格递增区间是第 5–25 波，相邻波比较从第 6 波开始。

同时核验每波计划总怪数能够容纳递增的飞行怪数。第 25 波仍必须至少有一只地面单位，因此第 25 波计划飞行数量必须小于该波总数量。递增会联动波次总怪数、role 构成、单体及合计 EHP、击杀收入、时间窗和经济账，须全部重算。若受到整数取整、波次总量、role 解锁、单关经济或 maxEnemyAlive 限制，不能实现该梯度，应在保留每关 25 波的前提下调整统一模型参数、各波怪物数量或组成并重新回算；不得降低梯度标准、漏掉后续波、丢弃待出生单位或只报告合计趋势。

报告同时给出计划数量 A_planned、实际成功出生数量 A_spawned、出生延迟和波次归属。容量上限导致延迟时，按原计划波次归属统计，待出生单位最终必须成功生成；完整回放结束后计划数与实际出生数须一致。即使 role 不是 air，只要运行时 IsFlying=true 就计入 A；反之 role=air 但 IsFlying=false 时不得计为空中单位。

### 5.4 EHP 及收入关系

本文 ΣEHP 是单位配置 HP 总和，不包含护甲。护甲折算后的伤害需求或实际承伤按 role 另报；区分理论 power × (1 − armor) 与仿真中的实际伤害，不得重复扣算护甲。

敌人数量、角色、HP、护甲、击杀奖励和清场奖励需一起建模。不得先给怪物加空中标签但实际仍走地面路线；为满足第 5–25 波飞行数量递增和第 25 波空地混合而调整组成时，同步检查整波 EHP、收入、role 首次登场、前后波关系、总怪数及出怪上限。

## 6. 需求 F：逐关独立经济与倒推标定

### 6.1 每关独立账本

每个 profile、每个 level 使用独立账本。上一关余额不得进入下一关。对预设 p、关卡 L、波次 w，采用以下量：

| 量 | 定义 |
|---|---|
| G0(p,L) | 本关开局 InitialGold |
| K(p,L,w) | 第 w 波成功击杀实际产生的金币；漏怪不计击杀奖励 |
| C(p,L,w) | 第 w 波实际触发的一次性清场奖励，按运行时条件结算 |
| R_combat(p,L) | 本关战斗收入 Σw(K+C)，不含开局金；用明确名称替代旧稿含义混用的 R |
| X(p,L,w) | 本波建造和升级实际支出 |
| V(p,L,w) | 本波出售退款；按 sellPrice、全局退款率及运行时取整逐笔计算 |
| B_open(p,L,w) | 波开始时账户余额 |
| B_close(p,L,w) | 本波所有真实结算后账户余额 |
| D(p,L) | 本关毛可用资金总量：G0 + Σ(K + C)；这是全关累计统计，不代表开局就可支配 |
| S(p,L) | 本关净支出：ΣX − ΣV |
| M(p,L) | 第 25 波结算后的本关余额，不结转到下一关 |

账本必须满足：

~~~text
B_open(p,L,1) = G0(p,L)
B_close(p,L,w) = B_open(p,L,w) + K(p,L,w) + C(p,L,w) - X(p,L,w) + V(p,L,w)
B_open(p,L,w+1) = B_close(p,L,w)
D(p,L) = G0(p,L) + Σw(K(p,L,w) + C(p,L,w))
S(p,L) = Σw X(p,L,w) - Σw V(p,L,w)
M(p,L) = B_close(p,L,25) = D(p,L) - S(p,L)
~~~

波次过程里塔操作只能使用操作当时已经到账的金币，不可借用未来击杀金或清场奖励。操作须记录准确时间或波次边界。同一帧有多个奖励、支出事件时按运行时代码事件顺序。

D 是全关累计毛资金，不是本关开局钱包。报告必须同时给每波现金账。不得使用旧式 D(L)=M(L−1)+R(L)、M(0)=0 的跨关资金链，也不得以全关总额大于满图价格证明玩家在任一时点买得起。

不得要求每关都满足 D−F≥0。只有逐波账证明本关能在相应时点购买时，才可称买得起参考布局。D<F 是合法结果，禁止虚增奖励、提前记奖励或强称“可建满”。战役 30 关收入与成本总计只可作描述性统计，不是可跨关调用的资金证明。

“波开始”和“波结束”在报表中须声明是否包含准备期操作及清场结算。本需求的账本把两次检查点之间的准备、建造/升级、战斗、奖励事件按时间完整记录；波前操作不能因为未发生在出怪期间而被漏记或重复记。第 1 波第一次支出前余额为 G0，第 25 波最终结算后的余额为 M。

### 6.2 倒推链及自由度

建模按“候选经济和塔位 → 有效战力 → 击杀进度 → EHP → 单体血量、数量、role → 出怪节奏 → 击杀/清场收入 → 逐波支付能力 → 正向仿真”的闭环迭代。每一关独立结算，玩家资金不跨关。

每关以本关独立经济和可实际执行的施工轨迹为标定依据，而不是以 L30 最终金币反推其余关。D 曲线是全关资金尺度的设计输入之一；用它和 G0 的候选值分配本关击杀/清场收入，再由生成的敌群及仿真事件回算收入，并在每个操作时点证明可支付，不能只以 D 的账面恒等式宣称闭环。

逐关报告参考布局一级施工费 F_route(p,L)、实战升级 U(p,L) 和实际卖塔重排损失，并与逐波资金和布局 W(p,L) 比较。第 25 波开始前逐笔核实已经到位的防御，不能提前计入第 25 波击杀金或清场金。旧的容量混合成本 F_C（C 座、约 50/30/20 三塔配比）只作历史预算对照，不要求补买会破坏长路线的剩余塔位。正文简写 F 时指 F_route，不指 F_C。

L30 的参考路线全三级或混合满级成本 E_max 可作末端可负担性诊断：E_max=Σ塔位(该塔三级累计投入)，同一种混合配比时可写为 W×Σ(配比_i×三级累计价_i)。另报退款与重排损失。比较的是本关收入在相应时点能支持的实际投入，不要求“通关后剩余的 M(30) 还能再买一遍全套塔”。不得强行以 M(30)≥E_max 取代实战建设证明。

逐项列出未知量及索引粒度（profile、level、wave、role），包括 InitialGold、收入/奖励规则、塔价、建造/升级序列、有效输出、π、ΣEHP、单体 HP、N、gap、库存上限、余额和退款。逐条列出独立方程、硬约束和派生关系。不得沿用未按索引展开的“八未知、五关系”或“七未知、三方程”口号宣称自由度闭合。

以下曲线及核心参数必须显式给出取值和理由；分析关系须说明单位、适用条件并进行量纲与运行时检查：

| 参数 | 含义与要求 |
|---|---|
| G0、D 的曲线形式及参数 | 各档各 30 关的初始金及毛资金预算；线性、几何或分段增长及全部系数，报告 L1 起手与 L30 实际状态 |
| k | 标准单位 TTK 秒；报告 role 和目标差异，不把单一 k 当全敌种事实 |
| π(p,L,w) | 目标击杀进度曲线；本轮末波按空中/地面分开结果验收 |
| τ | 升级每金有效产出 ÷ 新建每金有效产出；定义有效输出是否包含路径与空地收益 |
| r 或类似余量参数 | 若用，说明是同一关资金/布局成本的比较参数；不得解释成跨关累计余额 |
| N ≈ π × T_pass / k、gap ≈ k / π | 可作为候选耦合关系，但须给出符号单位和适用假设；N 与 gap 不能各自随意调到互相矛盾 |

τ 的分子是升级每金有效产出、分母是新建每金有效产出，因此 τ>1 表示在该定义和条件下升级每金产出更高，τ<1 表示新建更高。新增路径、空地覆盖、剩余塔位等外部收益另行计算；不可沿用旧文“τ>1 表示铺设优先”的反向解释。

T_pass 定义为指定路径和速度/减速条件下的无击杀通过时间；多 role、空地或动态路线须分别计算。原式 ΣH≈P_eff×π×L_path/v 及 H=f(P_eff,k) 只用于候选生成：P_eff 的单位须为生命/秒，L_path/v 为秒，护甲只在伤害侧扣一次。真实有效输出、覆盖、过量伤害、出生离散与目标竞争由仿真复核，不把近似式当作独立物理定律或验收证明。

数量与间隔的耦合必须在报告中显式计算和检查。若 N≈π×T_pass/k、gap≈k/π 在混合 role 或动态路径中不适用，应列出不适用条件，并给出替代的数量—出生跨度—并发存活关系及仿真证据；不得直接删掉耦合检查、把 N 和 gap 当作互不关联的两个旋钮。

数量 N 取整数、gap 换算为源字段精度后须再计算实际出生跨度；等间隔单列出生时首只到末只跨度为 (N−1)×gap。多组/分段编组按真实计划累计，达到存活上限时追加实际等待。不能用 N×gap 的近似隐藏首尾时序差。

当 N、gap 造成同时存活超过 maxEnemyAlive，或间隔低于运行时可处理节拍，应调整模型参数和波次设计，不得擅自提高引擎上限或丢单位。

必须说明三个设计选择：第一，资金曲线的形式、增长参数、30 个取值及两端状态；第二，长路线优先已确定，给出与塔量优先的翻转对照和收益差；第三，π 曲线采用线性收紧还是分段收紧，如何同时兼容前三波起手和末波两格标准。全局模型统一不等于一个全局倍率直接套完 30 关；逐关的系数、原因和验证结果必须公开。

### 6.3 击杀进度与金币到战力的定义

π 的候选设计曲线覆盖全部八档、30 关、每关 25 波，并分别定义地面/空中击杀进度。在静态等长路径的解析近似中，可写 π_last=1−d_last/L_path；这里 d_last 是该类别按时间最后被击杀单位的剩余距离，不是所有单位剩余距离的最大值。末波目标为 π_last≥1−2/L_path，并须在漏怪边缘留余量。实际死亡、抵达终点及漏怪事件由仿真判定，不能只检查一个 π 数字。

目标 π 曲线随波次单调收紧，给出完整的 25 波值与前几波的起手余量；压力波和实际结果的局部变化另列说明，不拿全关平均代替。若建塔造成动态改路，须记录参考路径、重算时点和各单位实际路径，最终验收以真实剩余距离为准，不能强套同一个 L_path。

金币到战力必须区分两阶段：

| 阶段 | 边际收益及公式要求 |
|---|---|
| 路线尚未完成 | 新塔本身的有效输出，以及堵捷径、拉长实际路径、重复覆盖和空中哨位收益 |
| 路线已完成 | 升级的边际输出与控制；若继续新建，必须说明其用途、是否改变路线和预算 |

参考布局一级施工折点 F_route=Σ_i(n_i×price_i,1)。只有所有一级塔同价时才能简写 W×P1，不能用单一 P1 代替不同塔种价格。逐关标明实际施工和升级阶段，给出折点两侧的边际产出/斜率；单凭 D≥F 不能证明第 25 波前已完成路线。

### 6.4 倒推步骤及硬边界

| 步骤 | 必须确定和报告 |
|---|---|
| 1. 布局态 | 长路线参考布局的路径、塔数、配比和等级；目标函数及排序 |
| 2. 本关成本 | F(p,L)；分开建造、升级、退款，并明确是否讨论重排损失 |
| 3. 本关初始资源与收入曲线 | G0 与逐波击杀/清场收入；不同预设 D01–D08 的参数及 30 关值 |
| 4. 战力 P | 建造阶段和升级阶段的分段有效输出斜率；折点 F；逐关所在阶段；覆盖率和 AOE 命中 |
| 5. 击杀进度 π | 每关 25 波完整曲线；末波地面、空中分别满足两格门槛；前期起手可玩；说明单调性和余量 |
| 6. 总 EHP | 按波次和地空拆分，说明由有效输出、时间窗、路径及击杀进度得到的推导 |
| 7. 单体 HP、数量和 role | H=f(P_eff,k) 等关系的假设；数量、角色血量比例及护甲进入公式的位置 |
| 8. 节奏 | gap 与单位出生时长、最大并发数和 maxEnemyAlive 的关系 |
| 9. 收入及余额 | 用成功击杀和清场事件回算 K、C；按真实事件顺序检查 B、S、M |
| 10. 回校 | 运行仿真，按输出差异回改明示的自由参数，记录至少两轮完整迭代 |

至少验证以下游戏性边界：

1. L1 每档起手资源应能支撑前 3 波，不在玩家学会玩法前失去可玩性。
2. 新建和升级都有合理用途；τ 不得等于 1 导致选择消失，也不能极端到让一种方案永远错误。
3. maxEnemyAlive=200 与最小出怪节拍约束全部遵守。
4. 不出现单发伤害轻易秒杀所有目标或持续无法击杀的极端；报告单发伤害/单体 HP 的上下边界及证据。
5. 本关余额和可负担性随地图差异可以变化；给出同档相邻关资源、支出与末余额的波动幅度、可接受范围和地图/塔位成因，不得通过跨关存款抹平。

满图一级、全三级、70%、50% 等均作为对照方案。塔数梯度是观察假设，不是新评价条件。

### 6.5 倒推锚点与经济表

输出所有 240 个 profile × level 组合。至少包含以下字段；需要时扩充列，并另附逐波数据：

| 字段 |
|---|
| profileId、levelId、W、几何容量 C、空场路径、参考路径长度 |
| G0、本关成功击杀收入、清场收入、D、参考布局建满成本 F、D 相对 F 的阶段判断 |
| 建造支出、升级支出、退款、净支出 S、末波余额 M |
| 有效战力 P、末波地面/空中 π、目标与实得 ΣEHP、偏差 |
| 怪物数量 N、role 构成、出怪间隔 gap、峰值存活数、状态与证据链接 |

偏差 = 实得 ΣEHP / 目标 ΣEHP − 1，必须能解释。表格的逐波经济数据须能复算，不能用全关汇总替代。每个结果状态标为 computed、offline_simulated、unity_reference 或 not_verified；只有存在同版本 Unity 场景或运行证据的记录才能标为 unity_reference。

原 prompt 的“15 列”又要求追加偏差列，且含已停用的上一关结转列；本版以以上明确字段为最低要求，交付时按实际列名声明总列数，不能仍标 15 列却输出 16 列，也不能保留跨关结转列当计算输入。目标 EHP、实际 EHP 与 N、gap 须说明是全关还是末波；汇总表优先给第 25 波数据，逐波附表补齐其余 24 波，不得混用。

### 6.6 F 类验收

- 240 个预设 × 关卡全部产生单独的数值、经济和模拟状态记录；6000 个预设 × 关卡 × 波次都有可索引输入/输出。
- 30 关各自独立开账，无跨关余额；逐波账本中每一笔收入、奖励、支出和退款符合事件顺序。
- D、S、M、G0、击杀收入和清场收入没有混用。
- 自由度清单按实际索引和独立关系逐条核算，模型可复算。
- 参数曲线、分段战力、π、k、τ 和单位明确；任何分析模型都不得冒充 Unity 结果。
- 每档、每关的候选至少经历两轮“倒推 → 仿真 → 修正”，保留改动原因和差异。
- 明确倒推不能决定的内容，如玩家临场操作、动态卖塔时机等；需靠实际策略试验或实玩数据补充，不得捏造结论。

回校时至少比较：完整通关零漏怪、全程/结算 HP、空地末波击杀位置、逐波资金、出生/清尾时长及总耗时。耗时原始结果留存供下阶段评价设计，本轮不要求“通关时间/旧 Par”通过。候选偏差超标时回改资金曲线、π、k、配比等明示自由参数，联动重新生成；不得绕开模型单独手填某关 H 来凑结果。每轮记录参数前后值、输入 hash、失败关波、变化原因和结果。

## 7. 需求 D：整体平衡性核算

### 7.1 供给模型

供给侧须可与敌人需求对算，并写出假设、失效条件和估计偏差方向：

| 现象 | 必须建模的原因 |
|---|---|
| 单体塔目标溢出 | 塔同一时刻只能打一个目标；路径覆盖段可能同时有多个敌人，不能用总 DPS × 时间简单乘出伤害 |
| 范围塔命中数 | 由路径单位长度密度、速度和出怪间隔决定，并按实际伤害半径/上限截断 |
| 减速放大效应 | 减速延长目标在火力区内的停留时间；价值取决于覆盖区实际火力、脉冲和叠加规则 |
| 覆盖率 | 只累计实际射程内的有效路径区段；报告交集被分为几段、重复覆盖和对地/对空差异 |
| 攻击时序 | 使用实际索敌、目标切换、CD、AOE、护甲、溢出、攻击结算和伤害位置 |

### 7.2 需求模型和压力比值

必须对比单波总 EHP、单只平均/分位 HP、role 与空地分量。不得用平均值隐藏首领、快怪或末波压力。计算从首只出生到末只抵达终点的时间窗，并纳入出怪间隔、数量、路径、速度和减速。

给出一个有单位定义的无量纲压力指标，例如“清完所需时间 ÷ 可用时间窗”，并由数据和仿真推导舒适、紧张、失败边缘三条阈值线及其来源，不可凭经验直接指定。

### 7.3 覆盖情景与代表结果

- 对 D01–D08 全部 30 关运行满图、70%、50%、满图不升级四档诊断布局。
- 第 1 关、中间关、第 30 关分别给完整计算过程；其余结果给全量表。
- 对纯地面波、含空中波、首领波各选至少一个案例详算；末波空地始终分开。
- “半图必须死、满图才可能五星”只作为研究假设。星级评价已暂缓，不能把“是否五星”拿来判断梯度；用零漏怪、HP、击杀位置、通关时间、有效输出和经济等原始指标报告结果。

### 7.4 必须回答的结论

1. 各档、各关满图一级（不升级）能否守住本关末波，余量多少，最小余量位置在哪里。
2. 升级带来的是通关能力还是时间/稳定性改善，用仿真和原始数值回答，不用形容词。
3. 经济在每个独立关卡内是否闭合：并列本关毛资金 D、参考路线一级施工费 F_route、全部升满成本 E_full、实际建造/升级净支出及末波余额；说明钱在每一波是否能及时花出、实际能升满几成塔、结余是否高到无处可花。旧满容量 F_C 另列，整战役总计只作描述，不暗示跨关购买力。
4. 防空是否成立：空中直线路径暴露时间、空中 EHP 占比、覆盖航线的有效塔位及实际输出必须单列，不可并入地面平均。
5. 若不平衡，定位到塔、经济、波次、地图或引擎上限，并给出有证据支持的最小修正方向；不得因此改变已确认的评价边界。

### 7.5 D 类验收

- 每个近似假设注明会高估还是低估、在哪些情形失效。
- 代表关的公式可手工复算。
- 解析估算、离线模拟、Unity 实测严格分开；未仿真结论标“待仿真验证”。
- 给出可复现命令、步长、种子、误差范围与模拟器近似。
- 满图、70%、50%、满图不升级均报告塔位生成算法、路线和合法性；可能改变结论的布局敏感性不可隐去。

## 8. 需求 E：对标《坚守阵地》的方法论

此项只比较机制和可量化方法，不搬运对方游戏数值，也不复述攻略。

### 8.1 七条机制逐项分析

| 机制 | 必须分析的本工程关系 |
|---|---|
| 路径塑形 | 建塔改变最短路、延长所有后续火力区的潜在射击窗口；与新增塔本身伤害区分 |
| 一线多段覆盖 | 射程范围与反复折返路径的交集分段数及其重复覆盖 |
| 减速前置 | 减速布在火力区前方时，目标进入主火力区前的速度和驻留变化 |
| 范围伤害与密度 | 实际队列密度、AOE 落点命中数与路径塑形的耦合 |
| 对空与对地分离 | 飞行走直线，空中暴露时间和有效塔位独立计算 |
| 升级与新建取舍 | 新建同时增加火力和可能的路径长度；升级增加属性但不增加路径塑形 |
| 卖塔重排 | 过渡塔被高效率塔替换的回收率、退款、重排时间及路线影响 |

每条必须填写：本工程有/无、实现位置（文件或字段）、可计算指标、达标线及来源、当前值与证据状态。

### 8.2 三套可复现策略模板

| 模板 | 构造 | 用途 |
|---|---|---|
| 只铺不配 | 使用最低成本塔铺设；明确塔种及合法塔位 | 检查三种塔分工是否必要 |
| 单一极致 | 分别测试全部资源集中在单体、范围、减速塔 | 揭示各类塔的优势和短板 |
| 混合策略 | 减速前置、单体补漏、范围输出、独立空中哨位等 | 检查混合是否改善原始战斗指标及其条件 |

每套给完整建塔次序、升级时机、卖塔时机、波次压力点和收入/支出。预期表现使用原始结果量化；不得写“最高星”或声称唯一星级最优策略。

原始策略期望“只铺不配能过但低星、混合应最高星”改为待检验的原始指标比较：只铺方案是否能守、单塔极致在哪些目标上受限、混合策略能否改善通过率/击杀位置/经济/时间。需报告是否出现单一策略长期支配其他方案的区间，以及成立条件；不预设一定存在唯一最优策略。

### 8.3 E 类验收

- 七条均有“有/无 + 实现位置 + 指标 + 达标线 + 当前值/证据状态”。

## 9. 需求 G：紧凑型数值、仿真和鲁棒性

### 9.1 唯一的正式末波判定

对每个 profile × level 的第 25 波，先按死亡时间选出各类别最后被击杀的单位，再取其死亡位置到该类终点的剩余距离。若同一最晚时刻同时击杀多只，列出这一组，并对该组中最大的剩余距离作判定：

~~~text
for category in {ground, air}:
    lastDeathTime = max(deathTime of wave-25 units in category)
    lastKilledGroup = wave-25 units in category with deathTime == lastDeathTime
    lastKillRemainingCells = max(deathRemainingCells of lastKilledGroup)
    require lastKillRemainingCells <= 2
~~~

以上为统计定义伪代码，实际计算以连续 25 波回放的死亡事件为准。第 25 波两类都必须存在、每类至少一只且本波全歼，因此两项都必须有数据并通过。不得只对已死单位求值而忽略漏怪或待出生单位。

该规则验收每类按时间最后死亡的单位，不要求每只单位都在两格内死亡。死亡事件须有单位唯一出生 ID、波次、地空类别、死亡时间、事件序号、位置和当时路径。不得以空地合并后的结果、全体单位剩余距离最大值或“已清空”代替。

同时按空地类别给全部死亡位置剩余距离的最小值、第一四分位数、中位数、最大值、超过 2 格的数量和比例。此处的分布最大值可以大于 2：那代表某只单位提前死亡，不等于“最后死亡的单位超标”。D 盘补充稿原有 max(所有 deathRemainingCells)≤2 的公式会误变成“每只都在两格内”，本版按用户确认的最迟击杀语义修正。

### 9.2 更严格的“所有单位两格内”只作可行性诊断

保留原始 prompt 的更严格口径可行性分析作为诊断任务，用于解释为何存在提前死亡，以及收紧到“每只都在两格内”要付出什么代价。它不改变已经确认的正式门槛，也不要求分析结果必须支持更严格口径：

1. 按 role 计算第 25 波单体 HP 最大/最小离散度。
2. H/2 的单位是生命/格，不是 DPS/格。无减速且速度为 v 时，最后两格驻留时间是 2/v 秒，所需平均有效 DPS 为 H×v/2；若用进入末段的剩余 HP，须显式注明并与原始配置 HP 区别。
3. 分地空统计末段两格可同时覆盖的合法塔位、实际射击窗口、有效 DPS 和减速；多速度或减速情况下用实际驻留时间和伤害积分比较，不将“塔位数×单塔 DPS”直接与 H/2 比较。
4. 同时检查前段是否必然提前击杀、AOE 和目标竞争，不能只证明末段火力够就声称所有单位都能最后两格死亡。
5. 对可达关给证据及余量，对不可达关给代价，如缩小末波 HP 离散、火力集中末段，以及是否造成前段失防、大量塔位闲置或布局选择消失。

此分析不能改变“按空地分别取最迟击杀”的唯一验收口径。

### 9.3 击杀距离与第 25 波编组

- 地面：在击杀事件时使用该单位当下生效的 A* 路径计算剩余路径长度。
- 空中：沿 S→E 直线计算击杀点至终点距离，不套用地面路径，也不以横纵分量代替沿线长度。
- 位置取 HP 首次降至零的真实伤害时点；若塔位造成存活敌人改道，按更新后的路径。
- 逐项记录格数转换、插值、边界和浮点误差；不得用取整方式隐藏超标。
- 编组侧另须验收每关第 5–25 波均有飞行怪且总数逐波严格递增；此规则按计划 IsFlying 数量计算，完整回放后再核对实际成功出生数量。
- 八档全部 30 关的第 25 波至少各含一只 IsFlying=true 与一只 IsFlying=false 的单位。两类数量、EHP、role 单独报告。
- 改组成以满足飞行递增或第 25 波空地共存时，必须同时复核整波 EHP、击杀收入、role 首次登场、前后波逻辑、总怪数和出怪上限。

### 9.4 仿真精度与 Unity 交叉校验

所有八档全部 30 关均运行确定性离线仿真。按 profile、level 建立 Unity 真实参考索引；没有同版本真实场景或运行证据的项目保留 not_verified，不能用离线数据标成 Unity 实测，也不能用少数参考关推定其余组合通过。

离线模拟器须披露路径平局、固定步长、float64、帧调度及其他近似。killed/leaked 对齐是必要但非充分条件；还需比较成功出生数、逐波击杀/漏怪、死亡位置、玩家 HP、现金事件、峰值存活、路径长度、出怪延迟、战斗/关卡耗时及其他关键运行指标。预检必须对每个 profile × level 独立断言 A(5)≥1 且 A(w)>A(w−1)（w=6…25）；离线与 Unity 回放分别核对计划出生和实际成功出生的飞行数量，不能将配置正确但运行时未生成齐全标为通过。

至少与本工程现有 .workbuddy/tools/balance_simulator.py 在相同输入和操作序列下交叉复算。不一致时逐项说明索敌节拍、AOE、寻路平局、伤害结算时序、光环/减速及帧步长的差异，明确误差方向与范围。旧工具可能附带旧评分输出，其星级结论在本轮不使用。离线程序的 passed 或退出码为 0 不等于本文件的紧凑性验收通过。

普通与火力塔按当前即时伤害建模；火力塔按真实落点和有效距离计算 AOE 命中；减速塔按真实脉冲、最强效果叠加、离圈余效及空地过滤建模。峰值存活达到 200 时记录出生延迟，不能丢掉待出生项目。逐波经济严格按到账事件，不得借用未来收入。

完整性验证必须从各关真实初始金币、初始塔态连续执行全部 25 波，包含逐波扩建、升级和卖塔。单独把第 25 波放到免费满配阵地上只能作诊断，不能认证本关可玩。轨迹中任何建造/升级资金不足、操作被拒绝、待执行操作未完成、非法封路、未出生完或中止都必须记录，不能当作完整通关。

### 9.5 EHP ±5% 硬性敏感性

对所有 240 个 profile × level 基准布局和操作序列，第 25 波分别进行目标总 HP/EHP +5% 和 −5% 试验。报告缩放施加层级、源 HP 字段类型和精度、必要的取整方式、实际得到的 ΣEHP、地空 role 是否保持及剩余差异；源字段允许浮点时不能无依据强行改成整数 HP。

两种试验固定基准塔位、建造/升级/卖塔时点及操作序列；不因扰动结果更换策略或补塔。前 24 波不变，第 25 波除声明的 HP 缩放与源类型取整外，保持数量、role、空地属性、速度、护甲、出怪节奏和奖励定义不变。空地各至少一只；两类缩放后实际 EHP 和相对基准偏差分别报告，不能仅给全波近似目标。

基准与两种扰动均必须达到：

- 地面最迟击杀 ≤ 2 格；
- 空中最迟击杀 ≤ 2 格；
- 漏怪 0；
- 玩家 HP 满。

任一失败即该组合未通过，须继续迭代数值；不得改成“只需不漏怪”、换口径或跳过某档。

### 9.6 减塔 −5% / −10% 鲁棒性对照

对每个基准布局按参考建造序列逆序移除塔，数量分别为 ceil(W×5%) 和 ceil(W×10%)。每步重新检查合法性并重新计算实际路线；若无法按固定规则完成，记录原因，不得私自换成更有利的移除集合。拆塔可能缩短路线，即使没有封路也不能继续沿用基准路径。

减塔试验不改主配置、不补塔、不改敌人。最低鲁棒目标为零漏怪及玩家 HP 满；还须完整报告空地最迟击杀是否仍 ≤ 2 格。若基准紧凑标准未通过，减塔结果不能代替基准验收。

### D.1 全 30 关的间距 1/2/3 几何对照

在 PowerShell 中执行。使用当前导出地图和已存在的只读几何函数，只向终端打印 CSV，Python 的 -B 禁止写字节码缓存。本机 python 命令当前解析到 WindowsApps 别名，因此下列命令明确使用已提供的 Python 运行时，不依赖该别名：

~~~powershell
Set-Location -LiteralPath 'D:\FishTestGame'
$balancePython = 'C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
@'
import csv
import json
import math
import sys
from pathlib import Path

project_root = Path.cwd()
sys.path.insert(0, str(project_root / ".workbuddy" / "tools"))
from balance_campaign import capacity, runtime_path_for
from balance_fill_gate import snake_walls

def read_table(name):
    path = project_root / "Assets" / "ConfigJson" / (name + ".json")
    return json.loads(path.read_text(encoding="utf-8-sig"))

scenes = sorted(read_table("tbsceneinfo"), key=lambda row: row["id"])
maps = {row["id"]: row for row in read_table("tblevelmap")}
if len(scenes) != 30:
    raise RuntimeError("Expected 30 levels; inspect current campaign dimensions")

writer = csv.writer(sys.stdout)
writer.writerow([
    "levelId", "mapId", "spacing", "buildableCells", "capacity",
    "wallTowers", "emptyPathSteps", "layoutPathSteps", "straightCells"
])
for scene in scenes:
    cells = maps[scene["mapId"]]["cells"]
    audit = capacity(cells)
    empty_path = runtime_path_for(cells)
    if not empty_path:
        raise RuntimeError("No valid empty path for level " + str(scene["id"]))
    straight_cells = math.dist(empty_path[0], empty_path[-1])
    for spacing in (1, 2, 3):
        walls = snake_walls(cells, spacing=spacing, augment=False)
        path = runtime_path_for(cells, walls)
        if not path:
            raise RuntimeError("Invalid layout for level " + str(scene["id"]))
        writer.writerow([
            scene["id"], scene["mapId"], spacing,
            audit["buildableCells"], audit["capacity"], len(walls),
            len(empty_path) - 1, len(path) - 1, round(straight_cells, 6)
        ])
'@ | & $balancePython -B -
~~~

该命令是固定蛇形构造的间距诊断，不包含独立空中哨位、不声称塔数或路径全局最优，也没有按三塔实际半径验证火力。地图坐标长度以格为单位；战斗死亡点的世界坐标换算仍须遵守正文规则。
