# 第 0 章 · 总纲

## 0.1 一句话需求

在这个 30 关 × 25 波的迷宫塔防工程上，**重建一整套自洽的数值体系**：三类塔的三级成长、每关 S 型迂回下的长路线布局、每关怪物构成与飞行怪梯度、塔与怪与波次与逐波经济的整体核算、以每关自有资金为锚的倒推标定，最后落成 30 关逐关可实际玩的数值表——每关末波地面与空中**分别**统计，各自最迟被击杀的单位都要落在距终点 2 格以内。

三条硬门槛同时成立才算完成：**空地各自最迟击杀 ≤ 2 格、零漏怪且满 HP（含 EHP ±5% 双向扰动）、第 5–25 波飞行怪存在且总数逐波严格递增**。

另有一条终局形态门槛：**第 30 关必须建满——除敌人路径占用的格子外，地图上不得留任何空格**（见 B.5）。

## 0.2 设计范式：每关独立账本，逐关倒推

本次不走"逐关试错、逐关凑"，也不走"用一个远端总目标支配所有关卡"。做法是：

**每关一套独立账本，同一个模型、同一套参数、同一个算法，逐关代入。** 区别只在输入——本关的初始金币、本关地图、本关能拿到的收入。**资金不跨关结转**：每关以本关 `InitialGold` 重新开始，上一关剩多少与下一关无关。这一条是硬规则，不是简化。

**锚在每一关，不在终局。** 每关用本关的钱，决定本关能建什么、怪物该多厚。第 30 关的满配只作**末端可负担性诊断**，不是推导起点，也不能反过来支配第 1 关。

这决定了全篇的组织方式：

| 角色 | 内容 | 位置 |
|---|---|---|
| **总方法** | 逐关账本、倒推链、自由度、回校 | 第 7 章 F（核心，但不是第一步做） |
| **输入准备** | 塔表、长路线布局、怪物统计 | 第 2–4 章 A–C |
| **校验手段** | 供需核算、对标检验 | 第 5–6 章 D–E |
| **最终产物** | 30 关紧凑型数值表 | 第 8 章 G |

**执行顺序不是章节顺序。** 实际动手应按：

```
1 核验工程版本、运行时表、代码、账户结算、地图合法性
2 B 长路线布局 → 拿到各关 W 与路径
3 A 塔表 → 拿到九行属性与价格
4 C 怪物统计 → 验证飞行怪梯度是否可行
5 F 逐关账本与倒推 → 生成候选
6 D 供需模型独立复核
7 全 30 关离线仿真 → 按明示自由参数回改 → 收敛
8 飞行怪递增断言、EHP ±5%、减塔 −5%/−10%
9 E 对标贯穿全程，最后成文
```

**倒推生成候选，仿真负责否决。** 两者冲突时，回到明示的模型自由参数与输入口径重新迭代，不得为迎合结果而私改单关数据，也不得用供需估算替代逐关仿真。

## 0.3 可推翻与不可推翻

"重新设计"若无边界，会滑向"重做游戏"。**必须在报告开头声明本表，并在后文每次把某个量当约束用时，回指它属于哪一类。**

| 类别 | 对象 | 状态 | 说明 |
|---|---|---|---|
| 数值 | 三类塔九行全部字段：价格、power、CD、radius、aoe、effect、卖价 | **可推翻** | 完全重设 |
| 数值 | 击杀金、清场金、波次奖励 | **可推翻** | 与塔价联动重设 |
| 数值 | 每波数量、每波总 EHP、单只血量、出怪间隔 | **可推翻** | 由倒推链算出 |
| 数值 | 怪物速度、护甲、role 权重、击杀奖励 | **可推翻** | 须与血量联动，不能单独调 |
| 数值 | 本关资金的**使用方式**（建塔与升级的分配顺序、卖塔重排） | **可推翻** | 但可花的总额受下一条约束 |
| 数值 | 初始金币 `InitialGold` | **固定为 100** | 30 关每关**严格等于 100**；源表、运行时表与仿真开局余额逐项核对，不得按关卡递增、不得分档、不得另行 override |
| 评价 | Par、1–5 星、任何旧星级阈值 | **本轮隔离** | 不设计、不校准、不验收；见 0.5 |
| 结构 | 三种塔 × 三个等级 | **不可推翻** | 玩法骨架 |
| 结构 | 30 关 × 25 波 | **不可推翻** | 战役骨架 |
| 结构 | S 型迷宫玩法、建塔改路、四方向寻路 | **不可推翻** | 核心机制 |
| 结构 | 对空/对地二分、飞行走直线 | **不可推翻** | 决定防空必须独立布点 |
| 结构 | 表结构与字段类型（`radius` 为 float、`prices` 为增量价） | **不可推翻** | 工程约束 |
| 结构 | 地图几何：格数、障碍、起终点 | **不可推翻** | 属美术资产；确需改起终点须单列理由与影响，不可静默改图 |
| 结构 | **L30 终局形态：除敌人路径占用的格子外，地图上不得留任何空格，所有可建格必须建满防御塔** | **新增硬门槛** | 见 B.5；这一条与"长路线优先"存在张力，须按 B.5 的口径处理 |
| 编组 | 第 5–25 波每波有飞行怪、第 6–25 波飞行总数严格递增 | **新增硬门槛** | 见 4.3 |
| 编组 | 第 25 波必须空地各至少一只 | **新增硬门槛** | 见 4.3 |
| 体验 | 第 25 波空地各自最迟击杀 ≤ 2 格 | **不可推翻** | 本次设计的收敛条件 |

> 判据：**改了就变成另一个游戏的，不可推翻；改了只是换个手感的，可推翻。**
> 由此推论：**现有配置不是约束，是待求量。** 用"现值就是这样"去否决一条推导，视为未完成。

## 0.4 通用口径约定

全篇适用，不再逐处重复。

| 约定 | 内容 |
|---|---|
| **距离单位** | 格。`cellSize = 1`，仍须读取实际值并报告世界单位与格换算 |
| **时间单位** | 秒；配置为毫秒的 `CD`、`spawnIntervalMs` 须标注单位并注明换算 |
| **速度单位** | 格/秒 |
| **EHP** | 配置 HP 之和。护甲**不并入 EHP**，在受击/伤害侧单独折算 `×(1−armor)`，避免重复扣算 |
| **地面剩余距离** | 击杀发生时，沿该单位**当时有效的 A\* 路径**到终点的剩余长度 ÷ `cellSize` |
| **空中剩余距离** | 击杀发生时，沿 S→E **直线轨迹**到终点的剩余长度 ÷ `cellSize`；不得套用地面路径，也不得以横纵分量代替沿线长度 |
| **死亡位置** | 伤害令 HP **首次降到零**时的单位位置。不取发射点、最后渲染帧或波次结算时刻。连续位置转格的插值与取整须固定、可复算，不得用向下取整隐藏超标 |
| **五类标注** | 每个数字必须标明来源：`measured` / `derived` / `simulated` / `inferred` / `not_verified`。五类不得混写 |
| **口径唯一** | 每个统计项只有一个定义。若存在其他算法，必须写出其结果差异及未采用原因 |
| **小数位** | 价格按源字段取整；DPS 保留 2 位；比值保留 2 位；比例保留 3 位；字段另有精度时服从 schema |

## 0.5 评价体系的边界（本轮不做）

本轮**完全不设计、不校准、不验收**任何星级或 Par 门槛。

- 现有星级、Par、星级阈值、"几星"**不得**作为新数值的目标函数或验收结论。
- "半图必须死、满图才可能五星"只是**待检验假设**，不得新增评分条件，也不得为让它成立而增删塔或改评价。
- 本轮只输出原始指标：零漏怪、HP、空地击杀位置、通关耗时、有效输出、逐波资金。耗时结果留存，供下一阶段从零设计评价体系使用。
- 不修改现有评分代码、存档或历史成绩。旧成绩是否保留、展示、迁移，待新数值结果形成后另行设计。

# 第 2 章 · 需求 A · 三类塔 × 三级的数值

## A.1 必须给出的字段

九行中每一行都要给全下列字段。字段名以工程 schema 为准，不要自创，不新增塔种或升级链。

| 字段 | 含义与要求 |
|---|---|
| 塔种 / 等级 / `upgradeTo` | 显示三塔分工与现有升级链，保持结构 |
| `power` | 普通/火力塔为整数单发伤害，逐级递增；减速塔恒为 0，**不要求**其随等级增长 |
| `CD` | 毫秒。攻击塔间隔逐级递减；减速塔按**光环脉冲周期**解释，说明级间变化与实际覆盖收益 |
| `radius` | 攻击/覆盖半径，逐级递增。**浮点字段，不得先取整后分析**；标注格数与源字段精度 |
| `aoe` | 仅火力塔，爆炸半径逐级递增，说明关联 `bulletId` 与字段来源 |
| `effectValue` | 仅减速塔，定义域 0–1，逐级递增；另报**运行时钳制上限**与"取最强有效效果"规则 |
| `prices` | 建造价与各级升级增量价，整数、逐级递增。**不得误写成累计费用**；给出梯度与累计换算 |
| 累计投入 / `sellPrice` / 真实退款 | 给公式；区分**表字段卖价**、**累计成本**、**`Global.sellRefundRate` 后实际到账**及运行时取整 |
| `searchIntervalMs` / `rotateSpeed` / `canAttackAir` | 适用则给数值；沿用须标注理由，修改须给影响范围，不适用写 N/A 并说明 |

**两条容易写错的派生关系**：

1. 累计投入 = 升级链各次 `prices` 之和。若沿用"累计投入 × 70% 向下取整"生成 `sellPrice`，须写出公式，并把全局退款率造成的真实到账差异另列。
2. 真实退款以当前代码为准。核对入口通常是 `max(0, RoundToInt(sellPrice × sellRefundRate))`，**不得**误写成"累计投入直接乘退款率"。取整方式与极端值处理都要能复算。

## A.2 每个字段必须能回答"为什么是这个数"

不接受"看起来合理"。下列问题各给一条明确回答，答案必须指向数字：

1. 建造价为什么是 A 而不是 A±20%？浮动时哪些关、哪些波次会**首先改变通过状态或紧凑性**？
2. 各级增量价倍率为什么如此？它与伤害、覆盖或减速增量的关系是什么？
3. 升级每金有效产出 ÷ 新建每金有效产出 = 多少？为什么是这个比例？
4. 三类塔在**建造阶段**的有效产出差异是多少、控制范围如何论证？不得把减速塔硬算成伤害 DPS。
5. 减速塔没有直接伤害，它的价值用什么可复算指标衡量？公式与前提是什么？
6. 哪些字段是**低敏感度参数**、哪些是**高杠杆参数**？敏感度结论必须由实际扰动或可复算依赖关系支持，不能只凭定性猜测。

## A.3 成长曲线与塔间比较

每类塔的每个成长字段都要给出：

- **曲线族**：线性 / 几何 / 凸 / 凹 / 其他明确定义的曲线，并说明为何选它。
- **逐级倍率表**：`L2/L1`、`L3/L2`、`L3/L1`。
- **每金产出**：累计投入与有效输出。单体塔报真实有效 DPS；火力塔报有效 DPS 并说明命中数怎么估；减速塔报等效价值并说明换算假设。
- **方向与拐点**：每金产出随等级递增还是递减、为什么必须这样；以及"从第几级起继续升级不如新建"的拐点，含阵地密度、剩余塔位、空地目标、路径变化、经济时点等触发条件。

**两条计算纪律**：

- 理论 DPS = `power / (CD/1000)` 只用于属性比值。正式有效 DPS 必须包含真实索敌、目标切换、冷却、护甲、AOE 命中与过量伤害。
- 减速塔**不得**因 `power = 0` 推出"价值为零"，也不得伪造成直接伤害塔。至少报告：覆盖时长、被减速敌人秒数、地空对象、以及与不放该塔相比火力区有效伤害/击杀位置的变化。脉冲间隔、持续时间、离圈余效**分开报告**；多塔重叠不相乘，弱减速是否延长强减速、效果切换与运行时钳制按当前 `BaseEnemy` 实现。

每金产出的公式与单位必须写清，并注明**新建是否包含延长路径与新增空地覆盖的收益**。

## A.4 A 的验收

- 对适用字段执行**表驱动**的单调性断言；不适用字段标 N/A 并说明，不伪造单调性。
- 累计价、卖价、退款能由公式与运行时规则复算，与表格一致。
- 任一字段变化都能追踪到派生值与受影响的「关卡 × 波次」结果。
- A.2 六项均给出可量化回答。

# 第 3 章 · 需求 B · 长路线布局与容量

## B.1 术语与合法性

| 术语 | 必须写明 |
|---|---|
| **S 型迂回** | 明确采用蛇形手指墙、螺旋或其他可复算构造；说明手指方向、间距、是否允许非均匀间距与斜向 |
| **"最大"** | 明确优化约束（通路连通、路径相对空场的长度要求、塔位覆盖等），不可只写"最大布局" |
| **塔数** | 墙体塔、参与路径塑形的塔、仅覆盖地面路线或空中航线的哨位塔**分别统计**，不合并成一个数 |
| **合法布局** | 使用工程当前的可建格、占格、不得封死路径、放置与重算规则；不得另造一套合法性定义 |
| **W** | 长路线参考布局的**实际塔数**。不等于几何容量 `C`，也不等于塔数最大解 |

## B.2 三种标尺与已定的优先级

逐关并列报告：

| 标尺 | 定义 | 用途 |
|---|---|---|
| **几何容量 `C`** | `B` 为原始合法可建格；`q` 为 0/1 最短路求得的 S→E **至少需保留的可建格数**；`C = B − q`。**`q` 不等于路径总格数** | 占用比例的分母；不得用选定长路线的 `W` 重定义 `C` |
| **塔数最大解** | 在合法 S 型构造下使塔数最大 | 报告"能摆多少"，不是默认最优 |
| **路径最长解** | 在合法构造下使地面敌人实际最短路径最长，并兼顾火力复用。**只能给"固定预算内的最好结果"，不保证全局最优**——最长诱导路径是 NP-hard | **本工程的正式布局方向** |

**优先级已定，不需要再论证选择**：采用**长路线 + 火力复用优先**。塔数只作报告指标，不进入任何评分或验收条件。

若路径最长解不是塔数最多解，必须量化报告：塔数差、路径差、单塔平均射击窗口差、以及原因。**塔数最大解保留为比较项，不得取代长路线参考布局。**

若三标尺恰好相同，复核定义与实现并给出证据；**不能为了预设"必须背离"而调整结果**。

## B.3 全关布局结果

每关至少报告：

- 地图尺寸、原始可建格 `B`、几何容量 `C`、`ceil(0.85C)` 的旧参考值（仅作历史对照）。
- 长路线布局实际塔数 `W`、墙体塔与哨位塔数量、保留通路格数、起终点、起终点直线距离、空场最短路径、布局后**实际 A\* 路径**。
- 塔数最大解与路径最长解各自的路径、塔量、火力覆盖与差异。
- 可按网格照摆的塔位坐标或字符图，区分墙、路径、起点、终点、塔。
- 每类塔对地面路径及空中直线路径的有效射击窗口、重复覆盖次数、攻击/减速贡献。
- 搜索算法、目标函数、地图输入 hash、种子、预算、合法性与最优性边界。
- 手指间距 1/2/3 格的塔量与实际路径长度敏感性，并解释趋势。
- 可建容量显著低于中位数的关卡（可用"低于中位数 30%"作筛查线），区分地图尺寸、起终点与障碍因素。

**三条纪律**：

1. 路径计算必须用**当前运行时四向 A\* 规则及平局顺序**，长度按实际移动步/连续段计，不用"希望敌人走的几何折线"替代。
2. 若沿用 `balance_maze.py`，须公开其字典序目标（实际路径长度 → 重复覆盖 → 参与塔位 → 较少无贡献塔）及各层筛选。该实现含固定半径采样近似，须以候选塔表**实际半径**与真实攻击记录复核。仅与空中航线射程圆相切、或只有几何交点，**不算**有效射击窗口。
3. 有限预算内的最优只能称"预算内最好结果"，**不能宣称数学全局最优**。不得为占用率补建既不输出、不减速、也不阻断捷径的塔。
4. **参考布局必须"两者取最优"，禁止只用 `snake_walls`。** 蛇形构造是确定性启发式，**不是最长路径算法**；实测 30 关里有 25 关搜索结果更优，最大差距达 18 格（L30：57 → 75）。必须并列报告 `snake_walls` 与搜索各自的结果、取最优、并给出达成率（路径长度 ÷ 理论上限）。只用蛇形会让 W、路径长度、填满塔数、覆盖率与 `F_route` 全线失真。

## B.4 塔量对照（诊断，非评分）

在几何容量 `C` 基础上完成四档诊断：`100% / 70% / 50% / 100% 不升级`。每档报告地图与路径、攻击输出、空地处理、击杀位置、漏怪、玩家 HP、经济。

- 若受 S 型结构或合法通路限制达不到目标塔数，记录目标、实际塔数与限制。
- 若受资金限制无法在实战买满，记录为**不可负担**。
- **不得**靠"开局免费满图"把诊断配置冒充可玩施工轨迹。

这四档是**诊断试验**，不是评分或验收条件。"半图必须死、满图才可能五星"只检验是否与结果相符；出现低塔数高表现等反例时照实保留。

## B.5 L30 终局填满（新增硬门槛）

**要求**：第 30 关的终局形态，**除敌人路径占用的格子外，地图上不得留任何空格**——所有可建格都必须建上防御塔。

### B.5.1 这条约束在数学上意味着什么

填满之后，可建格被劈成两半：

```
B = (路径占用的可建格 P) + (塔占用的格 T)
```

于是 `T = B − P`。**塔数不是可以自由挑的值**，它被路径长度反推：路径越长，塔越少；塔越多，路径越短。

所以 L30 的布局问题变成：**在 `T = B − P` 的约束下让 `P` 尽可能大**——在被塔填满的地图里找一条最长的唯一通路，而不是在空地图上随便摆塔。

**由此得到一条关键推论**：既然 `T = B − P`，"填满"就把 `T` 锁死成 `B − P`，那么**优化路径长度＝优化塔的覆盖面**——路径越长、铺得越开，塔就越容易打到它。这两件事不是对立的，是同一件事。下一节的实测会证明这一点。

### B.5.2 必须验证的三件事

1. **连通性**：填满后 S→E 仍连通，且不存在第二条捷径。若敌人最短路径短于设计通路，说明有多余开口，必须补填。
2. **路径长度不受损**：填满后敌人最短路径长度必须 ≥ 填满前参考布局的长度。若被压短，说明填充位置侵占了走廊。
3. **有效塔位占比**：**填满不等于全部有效**。分别报告总塔数、能覆盖至少 1 格路径的塔数、覆盖 ≥3 格的塔数、以及完全打不到路径的"废塔"数量与占比。

### B.5.3 实测：用蛇形构造会得出完全错误的结论

同一张 L30 地图（`B = 147`，17×9，4 个障碍），两种布局来源：

| 布局来源 | 参考塔数 | 路径长度 | 填满后塔数 | 有效塔数 | **废塔** | 覆盖率 |
|---|---:|---:|---:|---:|---:|---:|
| `snake_walls` 间距 2 | 58 | **57** | 91 | 68 | **23（25%）** | 74.7% |
| 搜索（3000 迭代 × 3 seed） | 58 | **75** | **73** | **73** | **0（0%）** | **100%** |

**同样是 58 座塔，路径能差 18 格，填满后的结果天差地别**：

- 用蛇形构造：路径最右只铺到 `x = 11`，右上角 `x = 12–16, y = 0–5` 整片没有任何路径格，那里的塔离最近路径 2.24–5.10 格，全部打空。填满后 91 座里有 23 座是纯摆设。
- 用搜索布局：路径铺满全图，填满后 73 座**全部**能打到路径，废塔 0，其中 69 座能覆盖 ≥3 格路径。

**所以"填满会有四分之一废塔"是蛇形构造的缺陷，不是填满的宿命。** 任何把这 23 座当成"填满的必然代价"的结论都是错的。

> **搜索预算本身是结果的一部分，必须公开。** 上表的搜索用 3000 迭代 × 3 seed；B.5.4 的 30 关对比为控制总时长只用了 2500 × 2，同一关 L30 从 75 格降到 69 格。这说明"路径最长解"没有唯一答案，只有"给定预算下的最好结果"。报告必须写明迭代数、seed 数与耗时，否则数字不可复现、也不可比。

- 三标尺与正式优先级齐全，长路线参考布局明确。
- 布局图可在编辑器中重建并通过当前合法性判定。
- 塔数与路径长度背离时有量化解释。
- 四档诊断齐全，并明确标注哪些是"不可负担"而非"设计失败"。
- **L30 满足填满要求**：无空格、连通且无捷径、路径未被压短；有效塔位占比、摆设塔数量与占比均已报告，且战力计算只计入有效塔位。

# 第 4 章 · 需求 C · 敌人构成、波次与 EHP

## 4.1 分类与数量口径

| 项 | 口径 |
|---|---|
| 空中 / 地面 | 以运行时 `EnemyConfig.IsFlying` 为准。`role` 与 `Type` 是独立属性，**不可替代** |
| 第三类 | 若存在既非纯空中也非纯地面的对象，按实际运行时行为说明；不得默认用"总数减空军"隐藏第三类 |
| 数量 | 同时报告**配置计划数、尝试出生数、实际成功出生数**及差异原因。`maxEnemyAlive` 造成的延迟须计入，待出生队列不得丢失 |
| 飞行怪数量 | 以运行时 `IsFlying = true` 判定，按每个 `level × wave` 统计计划数与实际成功出生数；`role` 名称不替代该判定 |
| 种类 | 同时报告 **canonical 家族数**与**实际战斗变体 ID 数**，并说明变体是否归入既有家族 |
| role | 按工程字典映射普通/虫群/快速/飞行/中型/重型/精英/首领。**空地与 role 是两个维度**，同一单位不得在两维内重复计数 |

## 4.2 必须给出的统计

按 `levelId + waveOrdinal` 唯一索引，至少给出：

1. **按关汇总**：总怪数、空中/地面数及数量占比、种类与变体数、总原始 EHP、空中 EHP 及占比。
2. **按波明细**：30×25 波的出生数量、空地数量与比例、`IsFlying=true` 飞行怪计划/实生数量及相对上一波的差值、role 数量、单体 HP 分布、该波 EHP、出怪间隔、收入、出生延迟。
3. **按 role 明细**：每关 role 权重与数量；每类 role 首次出现的关与波。
4. **单独标记**：空中单位首次出现波、空中占比最高波、压力峰值波。**不得以全关均值代替末波或峰值**。
5. **末波构成**：每关第 25 波的空地构成与空地 EHP。

按关实际数与 `expectedEnemyCount` 或波次配置总数不一致时解释差异。若某关之后不再引入新兵种，明确写出"自第 N 关起不再引入新兵种"。**空中数量占比与空中 EHP 占比必须分开报。**

## 4.3 飞行怪逐波递增（新增硬门槛）

对每一关分别检查，不能用其他关的数据代替。定义 `A(L,w)` 为该关第 `w` 波中所有运行时 `IsFlying=true` 单位的**计划出生总数**，跨不同飞行怪种类求和。此要求约束每波飞行怪**总数量**，不要求同一 `canonicalEnemyId` 或同一变体贯穿全部波次；各飞行怪种类及其数量仍须分别报告。

```
for w in 5..25:
    A(L, w) >= 1
for w in 6..25:
    A(L, w) > A(L, w - 1)
```

即第 5 波至少 1 只飞行怪；第 6 到第 25 波，飞行总数**逐波严格增加**，不允许持平或回落。数量为整数，故每次至少 +1。**不预设固定增量或固定增长公式**，具体数量须由统一模型推导并经仿真确定。该规则作用于全部 30 关。

**边界澄清**：
- 第 1–4 波**可以**出现飞行怪；本条不要求飞行怪只能在第 5 波首次登场，也不要求第 5 波数量大于第 4 波。
- 第 25 波仍必须至少有一只地面单位，因此第 25 波计划飞行数必须**小于**该波总数量。

**联动要求**：递增会联动波次总怪数、role 构成、单体与合计 EHP、击杀收入、时间窗与逐波经济账，须全部重算。若受整数取整、波次总量、role 解锁、单关经济或 `maxEnemyAlive` 限制而不能实现该梯度，应在保留每关 25 波的前提下调整模型参数、各波数量或组成并重新回算；**不得降低梯度标准、漏掉后续波、丢弃待出生单位，或只报告合计趋势**。

报告同时给出计划数 `A_planned`、实际成功出生数 `A_spawned`、出生延迟与波次归属。容量上限导致延迟时，按原计划波次归属统计，完整回放结束后计划数与实际出生数须一致。**即使 role 不是 air，只要 `IsFlying=true` 就计入 `A`；反之 `role=air` 但 `IsFlying=false` 时不得计为空中单位。**

## 4.4 EHP 与收入的关系

`ΣEHP` 是单位配置 HP 总和，不含护甲。护甲折算后的伤害需求或实际承伤按 role 另报；区分"理论 `power × (1−armor)`"与"仿真中的实际伤害"，**不得重复扣算护甲**。

敌人数量、role、HP、护甲、击杀奖励与清场奖励需**一起建模**。不得先给怪物加空中标签但实际仍走地面路线；为满足 4.3 与第 25 波空地混合而调整组成时，同步检查整波 EHP、收入、role 首次登场、前后波关系、总怪数与出怪上限。

## 4.5 C 的验收

- 统计总数与配置一致，不一致有解释。
- 种类数停止增长时，明确写出起点关卡。
- 空中数量占比与空中 EHP 占比分开。
- 每关第 5–25 波飞行数量序列与递增断言结果**逐关列出**，不合并成"整体趋势"。

# 第 5 章 · 需求 D · 整体平衡性核算

## D.1 供给模型

必须可与需求侧对算，并写出假设、失效条件与估计偏差方向：

| 现象 | 必须建模的原因 |
|---|---|
| **单体塔目标溢出** | 塔同一时刻只能打一个目标，覆盖段上可能同时有多个敌人；不能用"总 DPS × 时间"简单相乘 |
| **范围塔命中数** | 由路径单位长度密度、速度、出怪间隔决定，并按**实际伤害半径与上限**截断 |
| **减速放大效应** | 减速延长目标在火力区的停留；价值取决于覆盖区实际火力、脉冲与叠加规则 |
| **覆盖率** | 只累计实际射程内的有效路径区段；报告交集被分为几段、重复覆盖、对地对空差异 |
| **攻击时序** | 使用实际索敌、目标切换、CD、AOE、护甲、溢出、攻击结算与伤害位置 |

## D.2 需求模型与压力比值

必须对比单波总 EHP、单只平均与分位 HP、role 与空地分量。**不得用平均值隐藏首领、快怪或末波压力。**

计算从首只出生到末只抵达终点的时间窗，并纳入出怪间隔、数量、路径、速度与减速。

给出一个**有单位定义**的无量纲压力指标（例如"清完所需时间 ÷ 可用时间窗"），并由数据与仿真推导"舒适 / 紧张 / 失败边缘"三条阈值线及其来源，**不可凭经验直接指定**。

## D.3 覆盖情景与代表结果

- 对 30 关运行满图、70%、50%、满图不升级四档诊断布局。
- 第 1 关、中间关、第 30 关分别给完整计算过程；其余给全量表。
- 纯地面波、含空中波、首领波各至少一个案例详算；**末波空地始终分开**。
- 梯度假设只作研究项：用零漏怪、HP、击杀位置、通关耗时、有效输出、逐波经济等**原始指标**报告结果，不用"是否五星"判断。

## D.4 必须回答的五个结论

1. 各关满图一级（不升级）能否守住本关末波？余量多少？最小余量在哪一关？
2. 升级带来的是**通关能力**还是**时间/稳定性改善**？用仿真与原始数值回答，不用形容词。
3. 经济在**每个独立关卡内**是否闭环：并列本关毛资金 `D`、参考路线一级施工费 `F_route`、全部升满成本 `E_full`、实际建造/升级净支出及末波余额；说明钱在每一波是否及时花出、实际能升满几成塔、结余是否高到无处可花。**整战役总计只作描述统计，不暗示跨关购买力。**
4. 防空是否成立：空中直线路径暴露时间、空中 EHP 占比、覆盖航线的有效塔位及实际输出**必须单列**，不可并入地面平均。
5. 若不平衡，定位到塔、经济、波次、地图或引擎上限，并给出有证据支持的最小修正方向。

## D.5 D 的验收

- 代表关的公式可手工复算。
- 解析估算、离线仿真、Unity 实测严格分开；未仿真结论标"待仿真验证"。
- 给出可复现命令、步长、种子、误差范围与模拟器近似。
- 四档诊断均报告塔位生成算法、路线与合法性；可能改变结论的布局敏感性不可隐去。

# 第 6 章 · 需求 E · 对标《坚守阵地》的方法论

只比较**机制与可量化方法**，不搬运对方数值，也不复述攻略。

## E.1 七条机制逐项分析

| 机制 | 必须分析的本工程关系 |
|---|---|
| **路径塑形** | 建塔改变最短路、延长所有后续火力区的潜在射击窗口；与新增塔本身伤害**区分** |

| **升级与新建取舍** | 新建同时增加火力与可能的路径长度；升级增加属性但不增加路径塑形 |
| **卖塔重排** | 过渡塔被高效塔替换的回收率、退款、重排时间及对路线的影响 |

| 模板 | 构造 | 用途 |
|---|---|---|
| **只铺不配** | 用最低成本塔铺设；明确塔种与合法塔位 | 检查三种塔分工是否必要 |

# 第 7 章 · 需求 F · 逐关独立经济与倒推标定（设计主干）

## F.1 定位：每关一本账，锚在本关资金

现有数值一律作废，全部属于**待求量**。倒推不是"检验现值合不合理"，而是"从本关自有资金出发，把该关数值链算到底"的唯一主干。

**硬规则：资金不跨关。** 每关以本关 `InitialGold` 初始化，上一关余额不带入下一关。因此不存在"上一关省下来给下一关用"的通道，也不存在用全战役累计总收入证明某一关买得起布局的做法。

原始设想的链条是：

```
L30 最长路径 + 最多塔 → 全三级 → 最大经济 E_max
  → 各关金币 G(L) → 各关战力 P(L)
  → 怪物血量 H(L) → 数量 N(L) → 节奏 gap(L)
```

这个链条有两处必须改：

1. **不能用 L30 最终金币当唯一锚**。那样每关都要隔着 30 步去够一个不属于自己的数，任一关地图差异都会把曲线拧歪，而且第 1 关的起手难度会被第 30 关反向支配。
2. **不能用"上一关结转 + 本关收入"构成可支配额**。本关只能花本关 `InitialGold` 与本关到账的收入。

修正后的链条：

```
[1] 本关账本：G0 → 逐波收入 K/C → 逐波支出 X/退款 V → 余额 B
[2] 本关参考布局与施工轨迹（F_route）
[3] 战力 P：建造阶段与升级阶段的分段有效输出
[4] 目标击杀进度 π(L,w)，空地分别定义
[5] 该关需清掉的总 EHP
[6] 单只血量 H 与数量 N、role 构成
[7] 出怪节奏 gap
[8] 收入回算：由生成的敌群与仿真事件核对 K/C
[9] 逐波支付能力核验：每个操作时点余额是否够
[10] 正向仿真回校
```

## F.2 逐关账本的定义

对关卡 `L`、波次 `w`：

| 记号 | 含义 |
|---|---|
| `G0(L)` | 本关开局 `InitialGold`，每关重新初始化 |
| `K(L,w)` | 第 `w` 波成功击杀实际产生的金币；**漏怪不计击杀奖励** |
| `C(L,w)` | 第 `w` 波实际触发的一次性清场奖励，按运行时条件结算 |
| `R_combat(L)` | 本关战斗收入 `Σw(K + C)`，**不含开局金** |
| `X(L,w)` | 本波建造与升级实际支出 |
| `V(L,w)` | 本波出售退款，按 `sellPrice`、全局退款率与运行时取整逐笔计算 |
| `B_open(L,w)` | 波开始时账户余额 |
| `B_close(L,w)` | 本波所有真实结算后账户余额 |
| `D(L)` | 本关**毛可用资金总量** `G0 + Σ(K + C)`。这是全关累计统计，**不代表开局就可支配** |
| `S(L)` | 本关净支出 `ΣX − ΣV` |
| `M(L)` | 第 25 波结算后的本关余额，**不结转到下一关** |

账本必须满足：

```
B_open(L,1)    = G0(L)
B_close(L,w)   = B_open(L,w) + K(L,w) + C(L,w) - X(L,w) + V(L,w)
B_open(L,w+1)  = B_close(L,w)
D(L)           = G0(L) + Σw(K + C)
S(L)           = Σw X - Σw V
M(L)           = B_close(L,25) = D(L) - S(L)
```

**三条不可违反的记账纪律**：

1. 波次过程中，塔操作只能使用**操作当时已经到账**的金币，不可借用未来击杀金或清场奖励。操作须记录准确时间或波次边界。
2. 同一帧有多个奖励或支出事件时，按运行时代码的事件顺序处理。
3. **`D` 是全关累计毛资金，不是本关开局钱包。** 报告必须同时给出每波现金账。**不得**以"全关总额大于满图价格"证明玩家在任一时点买得起。

**不得要求每关都满足 `D − F ≥ 0`。** 只有逐波账证明本关能在相应时点购买时，才可称"买得起参考布局"。`D < F` 是合法结果，禁止虚增奖励、提前记奖励或强称"可建满"。

"波开始"与"波结束"在报表中须声明是否包含准备期操作及清场结算；两次检查点之间的准备、建造/升级、战斗、奖励事件按时间完整记录。第 1 波第一次支出前余额为 `G0`，第 25 波最终结算后余额为 `M(L)`。

## F.3 倒推链与自由度

建模按"候选经济与塔位 → 有效战力 → 击杀进度 → EHP → 单体血量、数量、role → 出怪节奏 → 击杀/清场收入 → 逐波支付能力 → 正向仿真"闭环迭代。每关独立结算。

每关以**本关独立经济与可实际执行的施工轨迹**为标定依据。`D` 的曲线是全关资金尺度的设计输入之一；用它和 `G0` 的候选值分配本关击杀/清场收入，再由生成的敌群与仿真事件回算收入，并在**每个操作时点**证明可支付——不能只靠 `D` 的账面恒等式宣称闭环。

**自由度必须按实际索引逐条展开，不得用"若干未知、若干方程"的口号宣称闭合。**

逐项列出未知量及其索引粒度（`level / wave / role`），至少包括：`G0`、收入与奖励规则、塔价、建造与升级序列、有效输出、`π`、`ΣEHP`、单体 HP、`N`、`gap`、存活上限、余额、退款。逐条列出独立方程、硬约束与派生关系。

以下曲线与核心参数必须显式给出取值和理由，并做量纲与运行时检查：

| 参数 | 含义与要求 |
|---|---|
| `D` 的曲线形式及参数 | `G0` 固定为 100；毛资金预算随关卡增长，线性/几何/分段及全部系数；报告 L1 起手与 L30 实际状态 |
| `k` | 标准单位 TTK（秒）。报告 role 与目标差异，**不把单一 `k` 当全敌种事实** |
| `π(L,w)` | 目标击杀进度曲线；末波按空中/地面**分别**验收 |
| `τ` | **`τ` = 升级每金有效产出 ÷ 新建每金有效产出**（见下） |
| `N ≈ π × T_pass / k`、`gap ≈ k / π` | **候选耦合关系**，须给符号单位与适用假设（见下） |

**`τ` 的方向必须写对**：分子是升级每金产出、分母是新建每金产出，因此 **`τ > 1` 表示升级每金产出更高，`τ < 1` 表示新建更高**。新增路径、空地覆盖、剩余塔位等外部收益另行计算。不得反向解释为"τ>1 表示铺设优先"。

**`N` 与 `gap` 的耦合是候选关系，不是物理定律**：

- 必须给出符号、单位与适用假设；`T_pass` 定义为指定路径与速度/减速条件下的**无击杀通过时间**，多 role、空地或动态路线须分别计算。
- 若在混合 role 或动态改路场景不适用，应列出不适用条件，并给出替代的「数量—出生跨度—并发存活」关系及仿真证据。
- **不得**因为它是近似的就删掉耦合检查，把 `N` 与 `gap` 当成互不关联的两个旋钮。
- 同理，`ΣH ≈ P_eff × π × L_path / v` 与 `H = f(P_eff, k)` 只用于**候选生成**：`P_eff` 单位须是生命/秒，`L_path / v` 为秒，护甲只在伤害侧扣一次。真实有效输出、覆盖、过量伤害、出生离散与目标竞争由仿真复核。

**数量与间隔的整数化**：`N` 取整、`gap` 换算为源字段精度后须再算实际出生跨度；等间隔单列出生时首只到末只跨度为 `(N−1) × gap`。多组/分段编组按真实计划累计，达到存活上限时追加实际等待。**不能用 `N × gap` 的近似隐藏首尾时序差。**

若 `N`、`gap` 造成同时存活超过 `maxEnemyAlive`，或间隔低于运行时可处理节拍，应调整模型参数与波次设计，**不得擅自提高引擎上限或丢单位**。

## F.4 九个环节

| # | 环节 | 必须确定与报告 |
|---|---|---|
| 1 | 布局态 | 长路线参考布局的路径、塔数、配比与等级；目标函数及排序 |
| 2 | 本关成本 | `F_route`；分开建造、升级、退款，并明确是否计入重排损失。**L30 的塔数不是自由取值**，由"填满"反推 `T = B − P`（见 B.5） |
| 3 | 初始资源与收入曲线 | `G0` 与逐波击杀/清场收入；30 关各自取值 |
| 4 | 战力 `P` | 建造阶段与升级阶段的分段有效输出斜率；折点 `F`；逐关所在阶段；覆盖率与 AOE 命中 |
| 5 | 击杀进度 `π` | 每关 25 波完整曲线；末波地面、空中**分别**满足两格门槛；前期起手可玩；单调性与余量 |
| 6 | 总 EHP | 按波次与地空拆分，说明由有效输出、时间窗、路径及击杀进度得到的推导 |
| 7 | 单体 HP、数量与 role | `H = f(P_eff, k)` 的假设；数量、role 血量比例、护甲进入公式的位置 |
| 8 | 节奏 | `gap` 与出生时长、最大并发数、`maxEnemyAlive` 的关系 |
| 9 | 收入与余额 | 用成功击杀与清场事件回算 `K`、`C`；按事件顺序检查 `B`、`S`、`M` |
| 10 | 回校 | 运行仿真，按输出差异回改**明示的自由参数**，记录至少两轮完整迭代 |

**环节 4 的分段必须写清**：

| 阶段 | 边际收益 |
|---|---|
| **路线尚未完成** | 新塔本身的有效输出，外加堵捷径、拉长实际路径、重复覆盖与空中哨位收益 |
| **路线已完成** | 升级的边际输出与控制；若继续新建，必须说明其用途、是否改变路线 |

折点 `F_route = Σᵢ(nᵢ × priceᵢ,₁)`。**只有所有一级塔同价时才能简写 `W × P1`**，不能用单一 `P1` 代替不同塔种价格。逐关标明实际施工与升级阶段，给出折点两侧的边际产出/斜率。**单凭 `D ≥ F` 不能证明第 25 波前已完成路线**——必须用逐波账证明。

**环节 5 的 `π` 必须给全，且空地分别定义**：

- 定义（静态等长路径的解析近似）：`π_last = 1 − d_last / L_path`，其中 `d_last` 是该类别**按时间最后被击杀单位**的剩余距离，**不是**所有单位剩余距离的最大值。
- 末波目标：`π_last ≥ 1 − 2 / L_path`，并须在漏怪边缘留余量。
- 实际死亡、抵达终点与漏怪事件由仿真判定，**不能只检查一个 `π` 数字**。
- 曲线随波次单调收紧，给出完整 25 波值与前几波起手余量；压力波与实际结果的局部变化另列说明。
- 若建塔造成动态改路，须记录参考路径、重算时点与各单位实际路径，最终验收以真实剩余距离为准。

## F.5 三个必须做出的设计选择

**选择 1 · `D` 的曲线**

`G0` **严格等于 100 且 30 关一致**（见 0.3），所以资金曲线完全体现在 `D`——即本关能产生多少收入。线性增长意味着每关增量相近；几何增长意味着后期收入越来越厚。选哪个、参数取多少，直接决定"后期是紧张还是宽裕"。
要求：曲线形式、全部参数、30 个逐关取值，以及 L1 与 L30 两端的实际状态（起手够不够、终局剩多少）。注意：`G0` 固定意味着**起手资源完全一致**，难度差异只能由地图与本关收入造成，不得靠调初始金来救某一关的手感。

**选择 2 · 长路线与塔量的取舍（已定，只需给对照）**

正式方向是长路线 + 火力复用优先。要求给出与"塔量优先"的**翻转对照**：两条曲线各自的塔数、路径长度、单塔平均射击窗口与最终表现差，用以证明这个优先级在本工程成立，而不是照搬。

**选择 3 · `π` 曲线的形状**

从 w1 到 w25，要求怪走多远才死？线性收紧还是前松后急剧收紧？
要求：给出形状与理由，并说明它如何同时容纳两个端点——"新手前三波不能被劝退"与"末波必须压到 2 格"。

## F.6 四条硬边界 + 资金波动

倒推法唯一的风险是"数学上自洽、玩起来不成立"。逐条验证并给出数据：

1. **L1 起手可打**：`G0` 换来的战力必须能撑过前 3 波。否则玩家在学会玩法前就被劝退。
2. **新建与升级都有用途**：`τ` 不得等于 1（否则选择消失），也不能极端到让一种方案永远错误。折点附近要存在"两种做法都说得通"的区间。
3. **数量与间隔受引擎限制**：`maxEnemyAlive = 200`、间隔不得低于引擎可处理节拍。超出就回改 `k` 或 `π`，不许硬压。

# 第 8 章 · 需求 G · 紧凑型数值、仿真与鲁棒性

## G.1 唯一的正式末波判定

对每一关的第 25 波，**先按死亡时间**选出各类别最后被击杀的单位，再取其死亡位置到该类终点的剩余距离。若同一最晚时刻同时击杀多只，列出这一组，并对该组中**最大**的剩余距离作判定：

```
for category in {ground, air}:
    lastDeathTime      = max(deathTime of wave-25 units in category)
    lastKilledGroup    = wave-25 units in category with deathTime == lastDeathTime
    lastKillRemaining  = max(deathRemainingCells of lastKilledGroup)
    require lastKillRemaining <= 2
```

以上为统计定义伪代码，实际计算以连续 25 波回放的死亡事件为准。第 25 波两类都必须存在、每类至少一只且本波全歼，因此两项都必须有数据并通过。**不得只对已死单位求值而忽略漏怪或待出生单位。**

该规则验收的是"每类按时间最后死亡的单位"，**不要求每只单位都在两格内死亡**。死亡事件须记录单位唯一出生 ID、波次、地空类别、死亡时间、事件序号、位置与当时路径。不得以空地合并后的结果、全体单位剩余距离最大值或"已清空"代替。

同时按空地类别给出**全部死亡位置剩余距离**的最小值、第一四分位数、中位数、最大值、超过 2 格的数量与比例。此处的分布最大值**可以大于 2**——那代表某只单位提前死亡，不等于"最后死亡的单位超标"。把两者混成一个数是最常见的口径错误。

## G.2 "所有单位都在两格内"只作可行性诊断

保留更严格口径作为**诊断任务**，用于解释为何存在提前死亡、以及收紧到"每只都在两格内"要付什么代价。它**不改变**正式门槛，也不要求分析结果必须支持更严格口径。

1. 按 role 计算第 25 波单体 HP 的最大/最小离散度。
2. `H/2` 的单位是**生命/格**，不是 DPS/格。无减速且速度为 `v` 时，最后两格驻留时间为 `2/v` 秒，所需平均有效 DPS 为 `H × v / 2`；若用进入末段时的剩余 HP，须显式注明并与原始配置 HP 区分。
3. 分地空统计末段两格可同时覆盖的合法塔位、实际射击窗口、有效 DPS 与减速；多速度或减速场景用实际驻留时间与伤害积分比较，**不得**把"塔位数 × 单塔 DPS"直接与 `H/2` 比较。
4. 同时检查前段是否必然提前击杀、AOE 与目标竞争——不能只证明末段火力够，就声称所有单位都能在最后两格死亡。
5. 对可达关给证据与余量；对不可达关给代价（缩小末波 HP 离散、火力集中末段等），并说明是否造成前段失防、大量塔位闲置或布局选择消失。

## G.3 击杀距离与第 25 波编组

- **地面**：击杀事件发生时，使用该单位**当下生效的 A\* 路径**计算剩余路径长度。
- **空中**：沿 S→E 直线计算击杀点至终点距离，不套用地面路径，也不以横纵分量代替沿线长度。
- 位置取 HP **首次降至零**的真实伤害时点；若塔位造成存活敌人改道，按**更新后的路径**。
- 逐项记录格数转换、插值、边界与浮点误差；**不得用取整方式隐藏超标**。
- 编组侧另须验收 4.3 的飞行怪梯度（按计划 `IsFlying` 数量计算，完整回放后再核对实际成功出生数）。
- 第 25 波至少各含一只 `IsFlying=true` 与一只 `IsFlying=false` 的单位，两类数量、EHP、role 单独报告。
- 改组成以满足梯度或第 25 波空地共存时，必须同时复核整波 EHP、击杀收入、role 首次登场、前后波逻辑、总怪数与出怪上限。

## G.4 仿真精度与交叉校验

全部 30 关均运行**确定性离线仿真**。缺少同版本真实场景或运行证据的项目保留 `not_verified`，不能用离线数据标成 Unity 实测，也不能用少数参考关推定其余关通过。

离线模拟器须披露路径平局、固定步长、float64、帧调度及其他近似。`killed` / `leaked` 对齐是**必要但非充分**条件；还需比较成功出生数、逐波击杀与漏怪、死亡位置、玩家 HP、现金事件、峰值存活、路径长度、出怪延迟、战斗/关卡耗时。

预检须对每一关独立断言 `A(5) ≥ 1` 且 `A(w) > A(w−1)`（`w = 6…25`）；离线与回放分别核对**计划出生**与**实际成功出生**的飞行数量，不能将"配置正确但运行时未生成齐全"标为通过。

至少与本工程现有 `.workbuddy/tools/balance_simulator.py` 在相同输入与操作序列下交叉复算。不一致时逐项说明索敌节拍、AOE、寻路平局、伤害结算时序、光环/减速、帧步长的差异，并明确误差方向与范围。该工具可能附带旧评分输出，**其星级/Par 结论在本轮不使用**；离线程序的 `passed` 或退出码 0 **不等于**本文件的紧凑性验收通过。

**完整性验证**：必须从各关真实初始金币、初始塔态连续执行全部 25 波，包含逐波扩建、升级与卖塔。单独把第 25 波放到免费满配阵地上跑，只能作诊断，**不能认证本关可玩**。轨迹中任何建造/升级资金不足、操作被拒绝、待执行操作未完成、非法封路、未出生完或中止，都必须记录，**不能当作完整通关**。

## G.5 EHP ±5% 硬性敏感性

对全部 30 关的基准布局与操作序列，第 25 波分别进行目标总 HP/EHP **+5%** 与 **−5%** 试验。报告缩放施加层级、源 HP 字段类型与精度、必要的取整方式、实际得到的 `ΣEHP`、地空 role 是否保持及剩余差异；源字段允许浮点时不能无依据强行改成整数 HP。

两种试验**固定**基准塔位、建造/升级/卖塔时点与操作序列，不因扰动结果更换策略或补塔。前 24 波不变；第 25 波除声明的 HP 缩放与源类型取整外，保持数量、role、空地属性、速度、护甲、出怪节奏与奖励定义不变。空地各至少一只；两类缩放后的实际 EHP 与相对基准偏差分别报告，不能只给全波近似目标。

基准与两种扰动均必须达到：**地面最迟击杀 ≤ 2 格、空中最迟击杀 ≤ 2 格、漏怪 0、玩家 HP 满**。任一失败即该关未通过，须继续迭代；不得改成"只需不漏怪"、换口径或跳过某关。

## G.6 减塔 −5% / −10% 鲁棒性

对每关基准布局，按参考建造序列**逆序**移除 `ceil(W × 5%)` 与 `ceil(W × 10%)` 座塔。每步重新检查合法性并**重新计算实际路线**；若无法按固定规则完成，记录原因，不得私自换成更有利的移除集合。拆塔可能缩短路线，即使没有封路也不能继续沿用基准路径。

减塔试验不改主配置、不补塔、不改敌人。最低鲁棒目标为零漏怪与玩家 HP 满；还须完整报告空地最迟击杀是否仍 ≤ 2 格。**若基准紧凑标准未通过，减塔结果不能代替基准验收。**

## G.7 逐关紧凑型数值表

每关交付表至少包含六组：

**A · 结构与布局**：关卡、地图尺寸、可建格 `B`、容量 `C`、长路线塔数 `W`、起终点、起终点直线距离、空场最短路径、布局后实际路径、坐标或字符图。
