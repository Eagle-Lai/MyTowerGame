## 一、总览

本工程为 Unity 2022.3.62f3c1 塔防项目（Built-in 渲染管线），采用「AOT 引导 + HybridCLR 热更 + YooAsset 资源」架构。顶层结构：

```text
<工程根>
├─ Assets/             Unity 资产与代码主体（2,403 文件）
├─ Luban/              配置表源头（Excel）与导出工具链（235）
├─ Docs/               设计/集成/交付文档 + UI 效果图（37）
├─ Packages/           UPM 依赖清单（2）
├─ ProjectSettings/    Unity 工程设置（26）
├─ Tools/              构建与运维脚本（2）
├─ .workbuddy/         AI 协作工作区：校验工具/项目记忆/过程截图（66）
└─ .gitignore / .gitattributes / .vsconfig
```

> `Library/`、`Bundles/`、`HybridCLRData/`、`ServerRoot/`、`Logs/` 等**本地产物**不入库，
> 由 Unity 与构建工具在使用时生成；当前工作区为清洁检出状态，这些目录尚未生成。

## 四、Assets 之外的目录

### 4.1 `Luban/` —— 配置表源头与工具链

- `Config/Datas/`：配置表源头——10 张业务 `.xlsx` + `__tables__/__beans__/__enums__` 注册表；注意混有 `.bak` 与 `_backup_*` 备份文件（见 §七-5）。
- `Config/Defines/__root__.xml` + `Config/gen.bat`、`gen.sh`：导出入口。
- `Tools/`：Luban 工具链二进制（Client / ClientServer / Excel2TextDiff 等）。

### 4.2 `Docs/` —— 工程文档与效果图

15 篇 `.md`（策划案、程序架构、HybridCLR / YooAsset / SQLite 集成、改名影响面、实施记录等）+ `ui_mockups/` 22 张 SVG 界面效果图；已镜像至云端资料库「自由人塔防 · 项目文档」。

### 4.3 `Packages/` 与 `ProjectSettings/`

- `manifest.json`：三个 git 依赖——HybridCLR `v8.14.1`、YooAsset `3.0.6`、UnityMCP `v10.3.0`；其余为 Unity 官方包。
- `ProjectSettings/` 关键文件：`ProjectVersion.txt`（2022.3.62f3c1）、**`HybridCLRSettings.asset`**（热更程序集与 AOT 补充元数据名单的权威源，需直接改 YAML 才落盘）、`EditorBuildSettings.asset`（Boot → Main 场景顺序）、`ProjectSettings.asset`（产品名 / 包名）。

### 4.4 `Tools/` —— 运维脚本（2 个）

- `build_android_sqlite.sh`：用 NDK 交叉编译 `libsqlite3.so` 到 `Assets/Plugins/Android/libs/<abi>/`（与 minSdk 22 对齐；Android 系统私有库不可直接 dlopen，必须随包自带）。
- `sync_to_server.sh`：把 `Bundles/<平台>/FreeTower/<版本>/` 与 `StreamingAssets/HybridCLR/*.dll` 覆盖式同步到本地服务器根 `ServerRoot/`（只拷贝不删除；版本号必须与构建一致，否则 404）。

### 4.5 `.workbuddy/` —— 随工程入库的协作工作区

- `tools/`：31 个 Python 脚本——`gen_*`（配置表/音频/怪物/关卡/UI 生成）、`apply_*`（批量改表）、`check_*`（9 类静态校验）、模拟与回归（`balance_sim`、`verify_save_roundtrip` 等）。
- `memory/`：项目长期记忆 `MEMORY.md` + 每日工作日志。
- `screenshots/`：23 张过程截图（工作留痕）。

## 五、目录之间的关系（关键链路）

1. **配置表链**：`Luban/Config/Datas/*.xlsx` →（菜单「导出配置表」/ `gen_code_json.bat`）→ `Assets/Gen/*.cs`（类型）+ `Assets/ConfigJson/*.json`（数据）→ 运行时经 `ResTable`（Bundle=Config）寻址加载。
2. **热更 dll 链**：6 个热更程序集（`Scripts` / `Gen` / `LubanLib` / 第三方两件 / `Assembly-CSharp`）→ HybridCLR `Generate ▸ All` → `HybridCLRData/HotUpdateDlls/` → 菜单拷贝 → `Assets/StreamingAssets/HybridCLR/*.dll` + `md5.txt` → `sync_to_server.sh` → 服务器 `{平台}/HybridCLR/`。
3. **AB 资源链**：`_UIAssets` / `Prefabs` / `Font` / `ConfigJson` 等 → `ResTable` 登记 → `FTBundlePackRule` 按表分包 → YooAsset 构建 → `Bundles/<平台>/FreeTower/<版本>/` → 服务器 → 客户端 `HostPlayMode` 下载（未开热更宏 = 离线玩法）。
4. **编辑器工具链**：`Assets/Editor/*`（含 `YooAsset/`）生成/维护 `Prefabs/`、`Scenes/`、`Art/Generated/`、UI 与配置；工具集反向引用热更程序集（`Runtime` / `Gen` / `LubanLib`）。
5. **引导链（场景）**：`Boot.unity`（纯 AOT）→ 加载热更 dll → `Main.unity`（热更 Runtime 接管）。
6. **文档/记忆链**：`Docs/` ↔ 云端资料库；`.workbuddy/tools` 校验脚本保障代码/资产一致性；`.workbuddy/memory` 沉淀每次工作结论。

## 六、整体组织的关键特点

1. **单一数据源 / 单一入口**贯穿全工程：寻址=`ResTable`、配置表源头=`Datas/*.xlsx`、服务器地址=`ResServerConfig`、时间=`GameClock`、存档=`SaveManager`、UI 布局=`UIPrefabBuilder`、本地化表=`gen_localization_table.py` 的 `ROWS`。
2. **AOT / 热更边界显式化**：目录级隔离（`AOTAssembly` 独立 asmdef）+ 接口契约（`IHotUpdateEntry`）+ 双场景引导（Boot → Main）。
3. **生成式资产管线**：预制体、UI、占位美术、配置、效果图均可由菜单/脚本重建；生成物入库但禁止手改（重导出会覆盖）。
4. **产物按「消费方」分链**：dll 走 AOT 侧独立 HTTP 链、AB 走 YooAsset——对应 `StreamingAssets/HybridCLR` 与 `Bundles/` 两个出口目录。
5. **防御式工程**：9 类静态校验脚本 + 多重指纹（`md5.txt`、`.baseline.stamp`）+ 导出保护（`KeepFilesInCodeDir`）+ 启动冒烟自检。
6. **工具与记忆随工程走**：`.workbuddy/` 入库，使协作脚本、日志、截图全部可追溯、可复用。
7. **文档双轨**：面向开发的 md 与面向设计的 SVG 效果图并存，并镜像云端资料库。

## 七、需要注意的结构问题

### A. 高风险（改动前必读）

1. **`Assets/` 根目录的孤立脚本是隐式契约**：`TestNull.cs` 是默认程序集 `Assembly-CSharp` 的唯一成员，而该程序集被纳入热更名单。今后任何放在 `Assets/` 根（或 asmdef 覆盖之外）的脚本都会加入此契约——**增删后必须重跑 HybridCLR 生成与 dll 拷贝**，否则真机报「缺少热更 dll」。
   建议：为 `TestNull.cs` 添加用途注释（保活兜底程序集），或为根目录脚本建立明确的 asmdef 策略。
2. **`Gen/` 是「半生成半保护」目录**：Luban 重导会删除它不认识的文件，`asmdef` 靠 `LubanExporter.KeepFilesInCodeDir` 备份/还原维系。改动该目录前先确认保护逻辑处于最新编译状态。
3. **编辑器工具依赖热更程序集**：`FTProject.Editor` 引用 `Runtime` / `Gen` / `LubanLib`，`FTYooAssetDefine.cs` 还引用 `ResServerConfig`。热更集签名变动会连带编辑器编译失败；方向不可反（AOT 严禁引用热更）。
4. **「多处同步」清单**：热更 dll 名单（2 处）、AOTMeta 名单（3 处）、服务器地址（2 处）、平台目录名（2 处）——漏改会造成运行时静默失败；现有菜单会自动比对告警，改动后务必核对。

### B. 整洁度与维护建议

5. `Luban/Config/Datas/` 混有备份文件（`__tables__.xlsx.bak`、`_backup_TowerInfo_before_M2.xlsx`），建议移出或归入归档目录。
6. `Docs/` 存在 v1/v2 双版本计划（`Tower_Interaction_Dev_Plan(.v2).md`）与过时过程报告，建议建 `archive/` 子目录收敛。
7. **零使用的第三方**：`Demigiant/`（327 文件）与 `Plugins/iTween` 当前均未使用，可评估移除以减小仓库/工程体积（移除前先全量搜引用与 dll 名单）。
8. `Plugins/Pixelplacement.meta` 是孤立 meta（无对应目录），Unity 会提示资产缺失，建议清理。
9. **未启用 LFS**：`.gitattributes` 仅 `text=auto`，而仓库含 82 个 dll、353 张 png、so 等二进制；其中 `StreamingAssets/HybridCLR/*.dll` 每次热更迭代都会产生 diff，建议评估 LFS 或改为构建期拷贝策略。
10. `Scenes/_Backup/main_before_builder.unity` 场景备份仍在版本库，确认无用后归档。

### C. 环境相关

11. 当前工作区为**清洁检出状态**：`Library/`、`HybridCLRData/`、`Bundles/`、`ServerRoot/` 尚未生成。首次打开 Unity 前留意：HybridCLR 需先执行 Installer（或迁移 `HybridCLRData`），否则 `Generate ▸ All` 会报 "must run Installer"。
12. 执行编辑器自动化操作前，先确认所连编辑器实例就是本工程（同名工具链可能在多个工程间共用端口）。
