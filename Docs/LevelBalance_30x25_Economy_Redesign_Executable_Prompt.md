## 0. 四项定案

| 定案 | 内容 | 为什么 |
|---|---|---|
| **D1 参考迷宫** | 保留开放地图与建塔改路。用确定性蛇形墙位（`snake_walls`）作为"塔数标尺"衡量铺满程度，**不写进地图数据** | 允许改路时，"占用"必须有一个明确的几何基准，否则半图/满图不可比 |

## 3. 本轮解决的问题

1. **半图通关**：旧配置下 L24 的 38 塔就差点通关、64 塔满血五星。根因是"每波产能≈需求 3 倍"+"升级太划算"（旧 L2 只贵 45 金就 +67% 伤害）。
2. **升级只加伤害**：现在每级伤害/攻速/射程同时涨，火力塔爆炸半径 0.75→0.90→1.05（新增子弹 id 6/7）。
3. **波次节奏偏松**：单波数量近乎翻倍、间隔压到 240ms，接近《坚守阵地》的持续压力流。
4. **部分地图迷宫过短**：L8/L9/L13/L19 的起终点同侧、L26 同边，参考迷宫只能建 24–49 座；已调整终点（L26 改为竖向）使墙位回到 50–60。

## 4. 三条不变量

- **I1 单调**：参考迷宫建成比例越高，总输出越高。实测曲线必须非降。
- **I2 替代率**：新建一座塔的边际产出必须显著高于升级。本方案 `P1=32`、`L1→L3` 额外花费 `258`、有效产能倍率 `m≈2.6`：新建 ≈33 输出/千金，升级 ≈6 输出/千金，比值 ≈0.19。
- **I3 预算**：`I/F`（总收入 / 满迷宫成本）落在 1.6–3.5；前期靠 `initialGold` 保证能起手，后期余钱只能进升级。

## 8. 验收闸门

以"参考迷宫建成比例"为档位，D04、合法初始状态、同配置：

| 闸门 | 档位 | 通过条件 |
|---|---|---|
| G1 | 0.50 | 失败：漏 ≥6 或 HP ≤10 |
| G2 | 0.70 | 失败：漏 ≥4 或 HP ≤16 |
| G3 | 0.85 | 不得结构五星（漏 0 + 满血 + 全杀） |
| G4 | **1.00** | 结构五星 + 建满 W 座 + 升级 ≥0.25×迷宫成本 + 战斗/Par ∈[0.90,1.05] |
| G5 | 1.00 禁升级 | 不得结构五星 |

L1–L5 豁免 G1/G2，L1–L14 豁免 G5。

**低档位必须用统一升级预算**（= 满迷宫档实际升级花费），否则少塔档会把省下的建塔钱全砸进升级，看起来比满迷宫还强。

## 9. 工程改造面

- `TowerInfo.xlsx` 的 `radius` 类型必须是 `float`；数据行由管线写入。
- `BulletData` 新增 id 6/7；`tbtowerinfo` 的 4/5/6 指向 2/6/7；`OWNED_FIELDS['tbtowerinfo']` 必须含 `bulletId`，否则 xlsx 静默丢字段。
- `bulletValues` 必须支持"追加新行"，只 update 已有 id 会漏掉 6/7。
- 任何表改动都要重算 `tblevelrating.runtimeContentHash`，否则 `Configs.IsLoaded=false` 拒绝开局；只有 `apply` 会做。
- `parCalibration` 写入顺序：冻结数值 → 取 `combatBasisHash` → 写 par → 重新 generate 断言 30/30 命中。
- apply/stage 必须用带 openpyxl 的解释器（`envs/default/Scripts/python.exe`）。
