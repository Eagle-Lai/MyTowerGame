## 三、先定义“铺满”与经济验收，避免封路和数字假象

### 3.1 地图容量

每张图输出以下数据：

```text
B = 地图中实际允许建塔的格子数，当前通常是'.'，不含S/E/P/#/X
C = 在仍保留至少一条合法S→E地面路径时，可同时存在的最大塔数
T(w) = 第w波检查点时场上实际塔数
occupancy(w) = T(w)/C
```

必须保留一条怪物通路，不能把“铺满”解释成封死地图。对当前静态单格模型，可将经过可建格的路径代价设为1，S/E/P等可走不可建格代价设为0，以0-1最短路求所需保留的最少可建格数 `q`，得到 `C=B−q`；如现场放置规则存在额外约束，补充约束并通过真实放置流程复核。不得把普通最短步数直接当q。

同时提交可复现的高占用合法布局、施工顺序、始终保留的路径和关键射击区。C是容量参照，不要求所有有效打法都沿理论最短保留通路；路线较长的阵地要诚实报告占用率与路径收益。

不得通过把大量可建格改为障碍/禁建格、缩小地图或将远处格子排除统计来降低铺塔成本。地图因战斗体验需要调整时，列调整前后B/C、理由、视野和实战证据。

### 3.2 钱必须在可使用的时间到账

按每一笔真实操作计算：

```text
cash(t) = initialGold + 已实际击杀收入 + 已结算清场奖
          + 已实际出售回款 − 已实际建造/升级/其他合法支出
```

- 所有操作时点 `cash≥0`；禁止预支未来击杀、以后波次清场奖或关卡结算奖励。
- 建造和升级沿用增量费用语义；累计投入、卖价及Global返还系数一起检查，防止重复折扣或卖塔套利。
- 总收入、当前现金、场上塔的累计购置成本、卖塔损失分别报告；不能把卖价和原塔价值同时当成新增财富。
- 击杀和清场仍只结算一次。失败、重开、继续和重复回调不得复制金币。

为每关制定明确的一级混合铺塔成本 `F(L)`：先以普通/火力/减速约50%/30%/20%作为预算比较样本，确定整数数量之和为C；执行者可调整该预算组合，但必须记录每种塔数量和实际成本。该组合只用于经济审计，不作为评分条件，也不要求玩家按固定比例造塔。

再根据合法参考回放确定必要升级投入 `U(L)`、实际调整损失和少量余量，联动确定收入目标。不能只以“全部买最便宜一级普通塔”证明正常混合阵地资金充足，也不要求给满图三级塔无限资金。

正式D04必须逐关满足：

1. 在第24波清场、**第25波开始前**，已有合法防守轨迹产生的资金和已建阵地，足够按同一施工计划完成C个一级混合塔位，并保留该轨迹必要的既有升级；不得依赖第25波最终清场奖。
2. 提供实际连续25波的大面积扩建参考：第25波开始前达到 `T≥ceil(0.85C)`，剩余现金足够补齐剩余合法施工格。它须在真实余额下完成并能取得五星，不能只是无限金展示图。若为了保留更有效路径选择更低占用，先尝试其他布局/地图适配；确实无法兼顾时明确列为未达标，不用改分母掩盖。
3. 开场不能直接获得终局铺塔金；资金随战斗展开而增加，前中期持续有合理的新建和升级机会。
4. 逐波输出收入和占用曲线，至少标出第1/5/10/15/20/24/25波；报告第24波时可负担的空位，避免只有最终总收入一行数字。

上述0.85是本Prompt用于把“尽可能铺满”转成可检验行为的默认实施目标，不是用户指定的原始数值；必须在报告中与用户原话区分。若它与真实路径玩法冲突，要提供证据并明确剩余差距，不能静默降低标准。

### 4.2 修复过度覆盖和升级收益失衡

保持三塔角色：普通塔稳定单体并补对空；火力塔地面范围输出；减速塔无直接伤害。允许不同布防思路，不增加永久成长、付费属性或新塔种来补经济。
