## 新增：预制体 Missing Script 批量清理编辑器工具

新增两个编辑器脚本（命名空间 `FTProject.EditorTools`，均置于 `Assets/Editor/`）：

- `Assets/Editor/MissingScriptCleaner.cs` — 核心逻辑 + 菜单入口
- `Assets/Editor/MissingScriptCleanerWindow.cs` — 可视化面板（EditorWindow）

### 关键实现要点（复用价值高）

- 文件夹递归枚举：`AssetDatabase.FindAssets("t:Prefab", new[]{ folderPath })` 默认递归子文件夹。
- 就地修改预制体的正确姿势：`PrefabUtility.LoadPrefabContents(path)` → 修改 → `PrefabUtility.SaveAsPrefabAsset(root, path, out bool success)` → **必须** `PrefabUtility.UnloadPrefabContents(root)`（放在 `finally` 中，否则预览场景泄漏对象）。
- 检测 Missing Script 的稳定方法：对每个 GameObject 建 `SerializedObject`，读 `m_Component` 数组，`objectReferenceValue == null` 即为残留脚本。比 `GetComponentsInChildren<Component>()` 返回 null 的方式更跨版本稳定。
- 移除用官方 API：`GameObjectUtility.RemoveMonoBehavioursWithMissingScript(go)`，需对 `GetComponentsInChildren<Transform>(true)` 逐个调用（该 API 只处理传入的单个 GameObject，不含子物体）。
- `PrefabUtility.GetPrefabAssetType` 只有接收 `Object` 的重载，**没有 string 重载**；需先 `AssetDatabase.LoadAssetAtPath<GameObject>(path)` 再传入。
- FBX 导入的 Model 预制体是只读的，`PrefabAssetType.Model` 应跳过；`Variant` 可处理但建议提醒复核继承关系。
- 大批量处理用 `EditorUtility.DisplayCancelableProgressBar`（返回 true = 用户取消）+ `try/finally` 中 `EditorUtility.ClearProgressBar()`。
- `EditorWindow` 中 GUIStyle 不要写成静态字段初始化（会在序列化阶段触发 Unity 告警），应在 `OnGUI` 里惰性创建。
- 点选定位顺序：先 `Selection.activeObject = asset` 再 `EditorGUIUtility.PingObject(asset)`，反了会被选中动作清掉高亮。

### 入口设计

- `Tools/资源工具/清理预制体 Missing Script/打开清理面板`
- `Tools/资源工具/清理预制体 Missing Script/清理 Project 窗口中选中的文件夹`（含 `[MenuItem(..., true)]` 校验器，未选中时置灰）
- `Tools/资源工具/清理预制体 Missing Script/预览扫描（不修改文件）`
- Project 窗口右键：`Assets/清理选中项中的 Missing Script`
- 三档安全反馈：预览模式 → 影响范围确认弹窗 → Console 可点击日志（`Debug.LogWarning(msg, asset)`）→ 结果面板逐条“定位”。

### 校验情况

本机无可用 C# 编译器（csc 被安全策略拦截），改用脚本做括号平衡 + 跨文件符号 + API 配对（Load/Unload、Begin/End ScrollView、ProgressBar/Clear）静态校验，全部通过；**尚未在 Unity 内实际编译运行，需用户在编辑器中打开确认无编译错误**。

## 项目文件夹分析（FreedomTower）

对 `D:\FreedomTower` 做了全量结构分析，结论要点：

- **性质**：Unity 塔防游戏《FreeTower / FreedomTower》，C# 开发，远端仓库 gitee.com/lai-zhangyin/freedom-tower，分支 main。作者署名 LaiZhangYin (Eagle)。
- **Unity 版本线索**：TextMeshPro 3.0.7 + com.unity.feature.2d 2.0.1 + ai.navigation 1.1.6 → Unity 2022.3 LTS 区间。
- **目录职责**：`Assets/Scripts`（62 个手写脚本，约 6.6k 行，全在 `FTProject` 命名空间）、`Assets/Gen`（Luban 生成的配置 C# 类，`cfg` 命名空间）、`Assets/LubanLib`（Bright.Serialization + SimpleJSON 运行时）、`Luaban/Config/Datas/*.xlsx`（策划配置源表）、`GenerateDatas/json`（导出的 json 数据）、`Assets/StreamingAssets`（运行时数据，json 目录当前为空）、`ttttt/`（已打包的 Windows Player 构建产物）、`tips.apk`/`tips.zip`（37MB 安卓包，疑似误入库）。
- **核心架构**：单例 Manager 模式（`BaseManager<T>` + `IManagerInterface`），`Launcher` 统一注册并驱动 EnemyManager / BulletManager / RoundCountManager / GameSceneManager / JsonDataManager / AStarManager；`EventDispatcher` 全局事件总线（事件名集中在 `EventName`）；`TimerManager` 定时器；`ObjectPool` 对象池；`UIManager` + `BaseView` UI 框架。
- **玩法闭环**：`Launcher` → `StartView` → 选关 → Main 场景 `GameSceneLauncher` 按 `SceneInfo` 配置加载地图 → 地图由 `BasePoint`(Normal/Start/End/Empty) 网格构成 → 拖动塔模型（`TowerPosition`）跟随鼠标，落在节点变绿即触发 `BuildTower()`，用 A* 校验是否会堵死敌人路径 → 塔建造成功后 `BuildSuccess` → `EnemyManager` 按 `GenerateEnemyEvent`/回合生成敌人沿 A* 路径行走 → 塔按 `FireInterval` 检测射击 → `BulletManager` 子弹命中扣血 → 回合/血量变化通过事件更新 UI。
- **数值配置**：`GlobalConst`（血 10、金币 100、10 回合、每回合 10 怪、塔攻击间隔 0.2s、子弹速度 25、敌人速度 12）+ Luban 表 TowerInfo/EnemyData/EnemyList/RoundData/SceneInfo。
- **已知问题（分析中发现）**：
  1. `ttttt/`（91MB 构建产物）、`tips.apk`、`tips.zip` 被纳入工作区/仓库，体积冗余。
  2. `Library/`（1.9GB）被追踪进 git（.gitignore 只忽略部分 ArtifactDB），git status 出现大量 Library 文件 D 状态，属异常。
  3. `Luaban/Config/Datas/` 存在 `~$*.xlsx` Office 锁定临时文件。
  4. `Luaban` 目录名拼写疑似应为 `Luban`（Assets 下同类目录 2026-09-25 已重命名为 `LubanLib`，但根目录旧名保留）。
  5. `Assets/Map`、`Assets/StreamingAssets/json`、`MyJson` 为空目录；`TowerCofig.cs` 类名拼写错误（应为 TowerConfig）。
  6. `Assets/Scripts/AStarWrapper/Scenes/SampleScene.unity` 示例场景混在脚本目录里。
  7. `tips.zip` 与 `tips.apk` 内容大小完全一致（38288423 字节），疑似重复文件。
