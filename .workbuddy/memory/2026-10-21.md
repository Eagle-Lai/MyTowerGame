## 产出「节奏重构 + 关卡表按关拆分」可执行 Prompt（只写文档，未改工程）

**交付**：`Docs/Prompt_节奏重构与关卡表拆分.md`（460 行）。用户诉求 = 参考《坚守阵地》节奏做紧张数值体系 + 关卡表从聚合改为每关独立；本轮只把需求改写为可执行 prompt，**没有任何配置/代码改动**。

**实测结论（Luban，隔离实验，不污染工程）**
- `__tables__.xlsx` 的 `input` 支持**逗号分隔多个 xlsx 合并成一张逻辑表**，导出单一 json，行序=声明顺序；子目录相对路径（`Levels/L01/RoundData.xlsx`）可用。
- 一个 xlsx 放多个 sheet **不可行**：Luban 会把所有 sheet 都按同一张表读入（实验里 `OtherData` 的 id=91 被并入 TBRoundData）。→ "每关一个工作簿装多张表"被否，只能"每关一个目录 + 每张表一个文件"。
- 跨文件重复主键会明确报错（`主键字段:'id' 主键值:'1' 重复`），拆错能被抓住。
- 实验环境：`Luban.ClientServer.exe -j cfg -- -d Defines/__root__.xml ...`，必须 `DOTNET_ROLL_FORWARD=LatestMajor`；`-d` 前要加 `--`，否则报 unknown argument；缺 `__beans__/__enums__.xlsx` 会失败。

**工程现状（写 prompt 的数据基础）**
- 六张关卡表全聚合：SceneInfo 30 / RoundData 750 / EnemyList 750 / LevelMap 30 / LevelRating 30 / EnemyData **10905**（132 原型 id<100000 + **10773 关卡变体** id≥100000，desc 含 `level=N; wave=M`）。
- 运行时链路 `SceneInfo.RoundList → RoundData → EnemyList → EnemyData`，`Assets/Scripts` 无 30/25 硬编码 → 拆表可 0 改 C#。
- 但 `Assets/Editor/LevelMapEditorWindow.cs` 的一键写入走 `.workbuddy/tools/apply_levelmap_export.py`，脚本硬编码 `Datas/LevelMap.xlsx`、`Datas/SceneInfo.xlsx`，**拆表必须同步改这个脚本**（C# 侧不用改）。
- `balance_pipeline.py` 里 `excel_write` 是单文件增量写；拆表要改 10 处（见文档 4.4），其中 `source_hashes()`、`commit_files()` 的删除事务最容易漏。
- 21 个历史脚本（`add_levels_*`、`apply_m2_*`、`gen_wave_data.py` 等）直写聚合表 → 标 LEGACY 不修。

**数值设计要点（prompt 里的量化口径）**
- 《坚守阵地》可信锚点：100 波 / 20 命 / 起手 $15 / 塔价 $5~$120 / 1x 约 30 分钟 = **18 秒/波**。
- 本工程差距不在总量（W1→W25 已 160×），在**开局太富（230=7 塔）、波间 5s 太长、坎只有 ×1.12**。
- 设计：`initialGold=100+20(L-1)`、`initialHp 20→12`、`autoNextRoundDelay 5000→2500`、`pressureMultiplier 1.12→1.42`、`finalMultiplier 1.14→1.55`。
- **两个源码坑（算波形必须知道）**：① W25 用 `finalMultiplier` **替代** `pressureMultiplier`（三元表达式），不叠乘；② 坎后首波被 `minBudgetGrowth=1.02` 兜底，所以 W6/11/16/21 环比只有 1.02——这正好是免费的"呼吸机制"，不要改 minBudgetGrowth。
- 校验只能"单调但坡度突变"，不能做真锯齿（validate 要求逐关逐波严格递增）。
- 仿真口径：`mixed` 漏怪不作失败判据（v6 下 L1 只能到 W20），通关判据改用 `balance_fill_gate.py` 驻防 reference。
