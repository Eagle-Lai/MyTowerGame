## 修复：tbaudio 未登记导致配置加载中止（启动阻断）

- **现象**：Console 报 `[Res] 资源地址表中找不到逻辑名「tbaudio」` → `tbaudio.json 读取失败` → `[Flow] 配置表加载失败，已中止建关`
- **根因**：M2 加音效表时 `Configs.cs` 的 `ConfigKeys`（9 张表）加了 `tbaudio`，但 `ResTable.cs` 只登记了 8 张，漏了 `tbaudio`；且 `tbaudio.json.meta` 的 `assetBundleName` 为空（其他 8 张都是 `config`）
- **修复**：ResTable 补一行 `{ "tbaudio", new ResAddress(ResBundle.Config, ...) }`；meta 补 `assetBundleName: config`。已提交 `1b5651ba3`
- **教训/盲区**：`check_code.py` 的「ResTable 逻辑名」检查只扫 `ResTable.Get("字面量")` 调用点，Configs 用字符串数组 `ConfigKeys` 集中声明，**不在覆盖范围** —— 这是此 bug 漏网的真正原因。以后给 ConfigKeys 加表时必须同步 ResTable（或给检查脚本补一条 ConfigKeys vs ResTable 的比对）
- **另发现**：工作区有 122 个 prefab + Range_Ring.png + DOTweenSettings.asset 的未提交改动，抽查确认是 Unity 重序列化重新分配内部 fileID（语义中性噪音），与本次修复无关，**留给用户决定是否提交**

## 减速塔改为范围光环（M3 / §Z.9）

用户要求："不需要指向怪物发射子弹，只要把进入攻击范围的所有怪物都减速。"

- **原实现**：发射减速弹命中单只怪 → 单体减速，怪群下几乎无用
- **新实现**：不索敌/不转向/不开火，持续把**射程内所有敌人**减速
  - `BaseTower.TickSlowAura`：按 CD 节拍遍历空间哈希，逐个 `ApplySlow(effectValue, CD+0.3s)`
  - `SlowAuraView`（新增，纯表现）：常亮射程圈（浅蓝）+ 命中脉冲，复用 `Range_Ring.png` 零新增资产
  - `TowerConfig.IsSlowAura` 按 `TowerType.Slow` 判定（**不用 effectType**，那是 UI 分类口径）
  - 配置：id 7/8/9 的 `bulletId` 4→0；射程 4/5/6 格、减速 50%/60%/70%、节拍 400/350/300ms
- **三个关键决策**：
  1. **按 CD 施加 + 时长 = CD + 0.3s** —— 若每帧刷 `ApplySlow`，怪的减速时长会被顶满，恢复时间取决于帧率；按 CD 结算才是确定的
  2. **光环子节点缩放要除回父级 `lossyScale`** —— 塔根有 0.8 缩放，不换算则光环比实际射程小 20%，与 `RadiusWorld` 判定对不上
  3. **结算与表现分两个节拍** —— 结算每 CD 一次，脉冲渐隐必须每帧（`TickVisual`）
- **保留未清理**：`power` 列（不参与运行）、`TBBulletData` id=4 减速弹（仍是合法定义）—— 清理会牵动 id 稳定性，收益为零
- 提交：`17d6aecae`；设计文档 §Z.9 有完整决策表

## 强力塔改为真·范围攻击（AOE / §Z.10）

用户要求："修改强力塔的逻辑，它是 AOE，也就是范围攻击的效果，不是单体攻击。"

- **现状缺陷**：强力塔（`TowerType.Aoe=2`，id 4/5/6）配的是 id=2 爆炸弹（`aoeRadius=1.2`），
  `OnHit` 里也确实有溅射逻辑 —— **但弹体必须先"追尾撞上"某只怪才触发**。
  于是表现为"单体攻击 + 一点溅射"：目标提前死亡/走位躲开就完全空放，溅射永不发生。
- **新实现**：AOE 弹飞向**发射瞬间锁定的落点**（`_aoeTargetPos`），到达即引爆，**不追尾**
  - `BaseBullet.Init`：`_isAoe = _aoeRadius > 0`；快照 `_aoeTargetPos = target.Position`；朝落点定向
  - `BaseBullet.Tick`：AOE 支路 —— 位移前判到达、位移后判到达/越点，到达即 `Explode(落点)`；
    超时（lifeTime）就地引爆而非静默回收
  - `BaseBullet.Explode(center)`：把原 `OnHit` 内联的溅射循环抽出复用，对落点半径内**全部**存活敌人造成伤害
  - `OnHit` 里若 AOE 弹撞到怪，也走 `Explode` 兜底
  - `TowerConfig.IsAoe`（按 `TowerType.Aoe`，与 `IsSlowAura` 同口径）
- **关键决策**：
  1. **落点发射瞬间快照、之后不可变** —— 跟着目标走就退化成追踪弹
  2. **到达即炸，不看落点上有没有怪** —— 伤害范围从落点算，这是范围攻击与单体攻击的本质分界
  3. **越点判定（`Dot(dir, 落点-当前位置) ≤ 0`）+ ε=0.08** —— 防高速弹 + 大 dt 一帧跨过落点永不判定
  4. **塔侧 `Fire(target)` 签名不变** —— "无目标绝不开火"不变量保留，落点由子弹从 `target.Position` 快照
- **未改动**：TowerInfo 强力塔行（数值本就对）、`aoeRadius`（属平衡）、未加独立爆炸表现
- 配置：`BulletData.xlsx` id=2 的 desc 同步为新口径；Luban 重导通过（`== succ ==`）
- 静态检查：`check_code` / `check_members` / `check_usings` / `check_unity_api` / `check_events` 全 PASS
- 设计文档 §Z.10 有完整决策表（G-A..G-H）
