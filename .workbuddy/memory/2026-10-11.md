## 热更入口改造：字符串反射 → AOT 接口（已完成）

### 需求
用户要求把 `BootLoader.InvokeHotUpdateEntry`（`EntryTypeName="FTProject.HotUpdateEntry"` + `EntryMethodName="Start"` 字符串反射）

### 实现（4 处）

| 文件 | 变更 |
|---|---|

### 关键点（易踩）
- ★ **AOT 侧不能 `new` 热更类型** → "找实现者"这一步**必须**保留反射。所以不是"完全去反射"，而是**把反射收窄到 `HotUpdateEntryLocator` 一个类一件事**：找到并实例化。拿到接口后全是强类型调用。
- ★ **实现类必须能被无参构造**（`Activator.CreateInstance`）→ 不能用 `static class`。这是 `HotUpdateEntry` 从 static 改普通 class 的原因。
- ★ **反向引用允许**：HybridCLR 只禁「AOT 引用热更」；热更 → AOT 是合法的。判据只看 AOT 侧是否零热更引用（FTProject.AOT 只引 `HybridCLR.Runtime`，✅）。
- ⚠️ 唯一残留字符串 = `HotUpdateEntryLocator.EntryTypeNames` 候选名。忘了同步也能跑（兜底全扫 + Warning），但每次启动全扫有性能开销。
- ⚠️ 兜底全扫用 `GetTypes()`（不是 `GetType(name)`），必须 catch `ReflectionTypeLoadException`（Unity 内置程序集常部分加载失败）并回退用 `e.Types`。

## ③ 本机热更资源服务器（用户问："怎么在本机搭一个资源服务器测热更？"）

### 先纠正的前提

用户以为要用 **WinSCP**，实际用不上 —— WinSCP 是**远端上传客户端**（SFTP/SCP），
本机测试根本没有远端主机。正解 = `python -m http.server`。

### 关键发现：热更代码**早已写完**，只差地址配置

排查后确认链路其实齐了：`Launcher` 有 `BootPhase.HotUpdate`、`HotUpdateView` /
`IHotUpdateLoader` / `EventName.HotUpdate*` 都在，`YooAssetResLoader.CheckUpdateCo`
也已实现"请求版本→比版本→换清单→差异下载→进度"。**唯一缺的是 HostPlayMode + 服务器地址**。
→ 于是补：地址配置 → `IRemoteService` → `HostPlayModeOptions` → `FT_HOTUPDATE` 宏
→ AOT 侧独立 dll 下载器 → StreamingAssets 预取。全链已通（静态校验 7 项 PASS）。

### ★ 服务器目录结构（最容易错的地方）

```
ServerRoot/
└── Android/
    ├── FreeTower/1.0.0/    ← AB：平台/包裹/版本/（version + bytes + hash + *.bundle）
    └── HybridCLR/          ← dll：与 FreeTower **平级**，不在版本目录里！
```
⚠️ 两条通道目录约定不同：AB 走 YooAsset（带版本目录），dll 走自写下载器（不带版本）。
⚠️ `ResServerConfig.ServerUrl` **只写到端口**，平台段是程序自动拼的；手写平台段 = 404。

### 已核实的环境事实（省得再查）

- 本机局域网 IP = **192.168.43.100**（WLAN 网卡，手机热点网段）；
  另有 `198.18.0.1` 是代理软件虚拟网卡（FlyingBird），**不是**局域网 IP。
- 已把该 IP 写入两处常量并保持一致：`ResServerConfig.ServerUrl` ↔ `BootLoader.ServerUrlForAOT`。
- ★ **`insecureHttpOption: 2` = `AlwaysAllowed`**（不是猜的：从 Unity 官方源码
  `Editor/Mono/PlayerSettings.bindings.cs` 查到 `NotAllowed=0/DevelopmentOnly=1/AlwaysAllowed=2`）
  → **明文 HTTP 已放行，不需要改 AndroidManifest**。
- `ForceInternetPermission: 0` 但 AOT 侧用了 `UnityWebRequest` → Unity 会自动加 INTERNET 权限。

### 端到端验证（已实测，19 个端点全 200）

`FreeTower.version`→内容 `1.0.0`；`FreeTower_1.0.0.bytes` 31219B；`.hash` 8B；
抽 3 个 bundle 均 200；**11 个 dll 全部 200**。0.0.0.0 绑定与局域网 IP 访问均通。

### ⚠️ 本次踩的坑：一条命令在错误目录执行

调试 `sync_to_server.sh` 时，一条 `cd <已删除目录> && rm -f *` 因 `cd` 失败
**回落到工程根**执行了 `rm -f *`。所幸 `rm -f` 不带 `-r` **删不掉非空目录**
（全部报 "is a directory"）→ **零损失**。事后核对：7 个关键目录全在，
`git status` 那 317 条 `D` 是**历史状态**（第三方源码目录在 2026-09-27「重新初始化仓库」
时就没入 git，文件仍在盘上），与本次无关。
★ **教训**：脚本里**不要用裸通配符 `rm -f *` 清目录**；`cd X && cmd` 中 `cd` 失败会让 `cmd`
落在当前工作目录。`sync_to_server.sh` 已改成**纯覆盖式拷贝（零删除）**，语义够用且无此风险。

### 关键认知（踩坑预防）

- ★ **YooAsset 本来就是 AOT**（PackageCache 源码包，已列 AOTMetaAssemblies）；"用它的代码"（YooAssetResLoader 1378 行）在热更层才是问题所在。
- ★ **dll 链路永远不该走 YooAsset**：Boot Awake 就要 dll，而 YooAsset 初始化要三步网络往返（version+manifest），鸡生蛋且更慢更脆。
- ★ YooAsset 3.0.x 默认值坑：文件下载 `timeout=0`（无总超时）、续传 `long.MaxValue`（关）、看门狗 `0`（关）、校验 `Low`（只验存在）→ **不显式传参等于裸奔**。
- ★ md5.txt 是 dll 链路唯一校验依据；只传 dll 不传它 → 客户端放弃更新（设计如此）。
