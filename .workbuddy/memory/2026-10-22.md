## 放置规则复核：补掉"改道漏怪"和"回塔心"两个洞（12:5x）

复核 11:50 那批改动，两条需求的骨架已经在（预览只画不改、怪物脚下可建、预览==实际），
但"怪物脚下建塔"的收尾有两个真缺陷，本轮修掉并补了回归测试。

1. **改道半径只覆盖半格 → 站在格角的怪会被漏掉**
   - 旧：`RerouteEnemiesNear(cell.Center, cellSize*0.5)`。格子是边长 CellSize 的方块，
     格心到四角是 0.707×CellSize，圆查询 + `sqrMagnitude <= r²` 会把靠角的怪排除在外；
     而它明明就在塔格里，主路径又没变（哈希判重不广播）→ 直接穿塔。
   - 新：`CombatSystem.RerouteEnemiesThrough(int row, int col)`，按"格"挑怪，不再按半径。
   - 顺带覆盖第二种漏网：**剩余路径会经过新墙格**的怪（下一格就要踏进塔，旧实现完全管不到）。
     判定用新增的 `BaseEnemy.RemainingPathTouches(row,col)`（只看 `_pathIndex` 之后，已走过的不算）。
2. **站在新塔格上的怪会先走回塔心**
   - A* 起点不受 IsWall 限制，所以 `UpdatePathByEnemyPoint(from)` 返回的路径首点就是 `from` 自己（现在是墙）。
     `SetPath` 只在"离首点 < 0.16 格"时才跳过首点，否则怪会朝塔的正中心走一步再绕出来 —— 视觉穿塔。
   - 新：`RefreshPath` 里若 `from.IsWall && newPath[0] == from` 就丢掉首点，直接朝下一格离开。
3. 删掉 `CombatSystem._queryBuffer`（改道不再用圆查询，留着会 CS0414 警告）；旧名注释全部改成 `RerouteEnemiesThrough`。

**新增回归测试** `Assets/Tests/BalanceCombat/PlacementPathPreviewTests.cs`（4 条，EditMode）：
