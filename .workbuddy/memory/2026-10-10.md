## ★★ 根治「Select a credential helper」弹窗（用户报告：每次提交都弹）

上面"那行吓人的报错"只是**症状**；本节是根因与根治。**已修复并验证。**

### 根因链（逐条有证据，非推测）

| # | 事实 | 证据 |
|---|---|---|
| 1 | PortableGit 的**系统级** `etc/gitconfig` 写着 `[credential] helper = helper-selector` | `git config --list --show-origin` |
| 2 | 取凭证时**先**调 `git-credential-helper-selector.exe` → 弹这个 GUI | 二进制里提取到 `Select a credential helper`/`Always use this from now on`/`<no helper>`/`credential.helperselector.selected` |
| 3 | 弹窗的 "Always use this from now on" 要把选择写进**系统级**配置，而 `etc/gitconfig.lock` **残留**（0 字节、mtime 08:30、25 分钟未被释放且无 git 进程）→ 写入失败 | 实测 `error: could not lock config file ...: File exists` |
| 4 | 写不进去 → 选择存不下来 → **每次都弹** | 用户长按观察 |
| 5 | 用户级已有的 `[credential "helperselector"] selected = manager` **不管用** —— selector 只认系统级那条 | `~/.gitconfig` |
| 6 | 仓库是 **public** → `fetch`/`ls-remote` 根本不需要凭证，**不会触发 helper** | GitHub API `"private": false` |

→ **所以"勾一下复选框就好了"是错的**：勾选要写系统配置，而系统配置当时**写不进去**。这也解释了为什么弹窗每次都来。

### 正解（git 官方文档原文依据，不碰安装目录）

`gitcredentials` 原文：
> If `credential.helper` is configured to the empty string, this resets the helper list to empty
> (so you may override a helper set by a **lower-priority config file** by configuring the empty-string
> helper, followed by whatever set of helpers you would like).

即：在**用户级**（优先级高于 system）插一条**空** `helper`，把 system 的 `helper-selector` 从列表里清掉，再挂上原来的 manager。

**实际改动（只有 `~/.gitconfig` 一个文件，已备份为 `.gitconfig.bak-20261010`）**
```
git config --global --unset-all credential.helper
git config --global --add credential.helper ""
git config --global --add credential.helper '!"C:/Program Files/WorkBuddy/resources/vendor/PortableGit/mingw64/bin/git-credential-manager.exe"'
```
- ⚠️ **保留原 helper 的字面值**（`!` + 绝对路径）：它一直在正常工作，别顺手改成裸名 `manager`。
- `credential.helperselector.selected = manager` **刻意保留**：万一 selector 被别处重新唤起，它还能少问一次。
- 另删掉残留锁 `etc/gitconfig.lock`（0 字节，非数据）。**系统 gitconfig 原样未动**（357 字节，mtime 仍是 Oct 8 22:32）。

### 验证（三步都要做，第三步最关键）
1. `git config --list --show-origin | grep credential.helper` → system 1 条 + 用户级 2 条（**空 + manager，顺序不能反**）；
2. `git push --dry-run origin main` → `Everything up-to-date`，**无弹窗、也无 `could not lock config file`**；
3. ★ `printf 'protocol=https\nhost=github.com\n\n' | git credential fill >/dev/null` → **exit=0 且 stderr 为空**。
   这一步是**决定性证据**：若 selector 还在，GUI 会阻塞（被超时打掉，exit=124）；若没有任何 helper 能提供凭证，
   git 会退回终端交互并报 `could not read Username`（exit≠0）。两者都没发生 ⇒ 凭证链已直连 manager。
4. 事后确认锁**未复现**、系统 gitconfig 未被改动。
