## [家用D] 修 bug：选关界面点「返回」没回主菜单
- 现象：关卡选择界面点 Back，界面消失但屏幕只剩背景（既没回主菜单也没回对局）。
- 根因：**选关没有自己的场景**，它是叠在主菜单上的整页界面（`OnStartGameRequest` 先 `Close(MainMenuView)` 才开选关）。
  而 `GameFlowManager.OnCloseSelectRequest()` 原实现**只 `Close(SelectView)` 就 return**，不负责"下一步去哪" → 就剩空背景。
- 修复（`Assets/Scripts/Game/GameFlowManager.cs`，仅此一处）：
  - `State == None`（主菜单进来的选关）→ `Open<MainMenuView>()` 回主菜单；缺 prefab 时降级 `OpenSelectOrFirstLevel()`。
  - `State != None`（对局中 `QuitToSelect` 进来的选关）→ `TeardownLevel()` → `State=None` → `ResetGameSpeed()` → `InitLevel(Level.Id)` 回对局。
- 验证（Unity MCP 编辑器实测，同一流程跑两遍一致）：`StartGame` → `SelectView`；`CloseSelect` → `MainMenuView`。静态校验 7 个全 PASS。
  ⚠️ `check_usings.py` 报 `BuildApk.cs` 缺 `using YooAsset.Editor` 是**既有误报**：那里的 `BuildResult` 实为
  `UnityEditor.Build.Reporting.BuildResult`（同文件头部已 using），与该工具的类型表撞名，与本次改动无关。
- ★ 经验：**"整页界面"的返回要先想清"回到哪一层"**。本工程整页界面分两类：`TowerCodexView`（自己 `Close` + `Open<MainMenuView>`）、
  `SelectView`（发 `CloseSelectRequestEvent` 交给 Flow）。加新整页界面时照 `TowerCodexView` 的写法最省事。

## [家用D] 修 bug：手改 SelectView/SelectLevelItem 后横向选关失效（不滑动）

- 现象：手改两个 prefab 后，运行期选关画廊**完全不能横向移动**、只显示 1 张卡。
- ★★ 根因（**SuperScrollView 视口快照 + 初始化时机**，非常易复发）：
  1. `LoopListView2.InitListView()` 一次性把 viewport 的 `GetLocalCorners` **快照缓存**到 `mViewPortRectLocalCorners`，
     之后所有"显示/回收/吸附"都用这份缓存，永远不再重取。
  2. `SelectView.Build()` 原先在 `OnEnable` 里直接 `InitListView` —— 那时 Canvas **还没排版**，
     手改后 `List`/`Viewport` 是拉伸型（锚点 0,0/1,1）→ 宽 = 0（Viewport 拉伸减去左右 inset 甚至算出 **−400 宽**）。
     插件缓存了一份**负宽视口** → 只留 1 张卡、横向完全不动。
- 修复（两处，缺一不可）：
  - `Assets/Scripts/UI/SelectView.cs`：新增 `_pendingInit`；`Build()` 只挂标记，真正 `InitListView` 拆到

- ★ **硬约束（血泪）：Viewport 宽必须**恰好**等于卡片宽，且为固定尺寸**。卡片 1500 时视口必须也是 1500；

## [家用D] 真机调试链路：nova 14 Ultra（HarmonyOS 6.1）抓 freedomtower 日志 — 结论：走不通

用户目标：看 APK `freedomtower` 在手机上的运行日志（它跑在华为「卓易通」里）。

- 手机 = **nova 14 Ultra / MRT-AL10 / HarmonyOS 6.1.0.145（纯血鸿蒙，不是安卓）**。
- ★ **纯血鸿蒙不走 adb**：USB 上手机接口被识别成 `HDC Device`（华为私有协议，VID_12D1&PID_5000），
  `adb devices` 永远为空；驱动由「华为电脑管家」自带，Android Studio 用不了。要连只能用 **hdc**（DevEco 工具链）。
- 本机装 hdc：从华为开发者站下 **Command Line Tools for HarmonyOS (windows-x64-6.0.2.670, 2.4GB)**，解压得
  `.../sdk/default/openharmony/toolchains/hdc.exe`（本机放在 `D:\Android\hdc-tools\`，hdc 3.2.0c）。
- ★★ **hdc 无线连接的两个关键坑**（血泪）：
  1. **无线调试没有"配对码/二维码"是正常的**（华为官方论坛确认：鸿蒙 6.x 只给 IP:端口，电脑侧直接 hdc 连，不需配对码）。
  2. **`hdc tconn` 的连接不能跨进程保持** —— 每次单独跑 hdc.exe 都会新起 server，之前连的无线设备就丢了
     （表现为第一条命令静默返回、之后全是 `Not match target founded`）。
     **解法：必须在同一个脚本/进程内 `start -r` → `tconn` → 执行命令**，或先 `hdc start -r` 让 server 常驻。
     已封装 `D:\Android\hdc-tools\hdc_session.sh`。
  - 成功的连法：`hdc start -r` → `hdc tconn 手机IP:端口`（提示 Connect OK）→ `hdc -t 手机IP:端口 shell ...`。
- ★ **卓易通 = LXC 容器**（华为 isulad 引擎）。进程里能看到：`anco_service_broker`、`virt_device`、`anco_audio`、
  `root ... lxc-start -n <64位哈希> -P /mnt/isula/var/lib/isulad/engines/lcr ...`。
  容器名如 `49ce1827...649dc`。数据在 `/data/virt_service/rgm_hmos/anco_hmos_data/`。
- ★★ **结论：hdc 抓不到卓易通内 freedomtower 的日志** —— 容器独立 PID 命名空间（鸿蒙侧 ps 看不到安卓 app 进程），
  且 `/data/virt_service/`、`/mnt/isula/var/run/isulad/` 全部 `Permission denied`（需 root，华为不给）。
  `bm dump -a` 也看不到卓易通（它是系统级虚拟化服务，不是普通应用）。
- **建议正路**：① 若有真安卓手机，直接用那台调（adb+logcat+Unity Profiler 全通）；② 或 Unity 打包勾
  「Development Build + Autoconnect Profiler」让编辑器直连真机看 Debug.Log（但在卓易通虚拟化下大概率连不上）；
  ③ 卓易通这条路对安卓游戏调试是地狱难度，不建议继续投入。
